# 근거 기반 여정 동반자 v5 — 사전 평가

## Executive Summary

- **결론: 설계 초안으로는 공유 가능하지만, 운영 적용은 보류해야 합니다.** v5는 `E_부모동행v6` 테스트에서 드러난 미검증 용어 자동 보정과 위기 대응 순서 누락을 명시적으로 보완했습니다. 그러나 v5 자체를 50문항 회귀셋으로 실행한 결과는 아직 없습니다.
- **기존 E의 검색 반영은 강점이지만 품질 통과 증거는 아닙니다.** E는 50문항 중 46건(92%)에서 검색·인용을 반영했으나, 골든 답안이 있던 10문항에서 정확도 50%, 할루시네이션율 50%로 모두 기준을 넘지 못했습니다.
- **배포 차단 요인은 프롬프트 밖에도 있습니다.** 빈 검색·미검증 용어의 코드 폴백, 위기 자원의 운영 설정 주입, 맥락 카드 API, 문장별 인용 귀속 검증이 없으면 v5의 지시만으로 같은 실패가 재발할 수 있습니다.

## 평가 대상과 방법

| 항목 | 내용 |
|---|---|
| 대상 프롬프트 | `가정연합 축복 챗봇 시스템 프롬프트 v5 — 근거 기반 여정 동반자` |
| 평가 성격 | 기존 회귀 결과를 근거로 한 문서·설계 사전 평가 |
| 직접 실행 여부 | 미실행 — v5 응답 생성 및 채점 결과 없음 |
| 비교 근거 | `E_부모동행v6`와 `03_여정동반자_개선`의 2026-07-29 회귀 결과 |
| 과거 실행 환경 | gemini-3.5-flash-lite, RAG 테스트 봇 D-1 ver2(봇 11), 회귀셋 50문항 |
| 중요 제한 | 정확도·할루시네이션은 골든 답안이 있는 10문항만 채점됨. 나머지 40문항은 미채점이므로 통과로 해석할 수 없음. |

## 기존 결과: 검색 반영은 개선됐지만 정확성은 미달

| 지표 | E_부모동행v6 | 03_여정동반자 | 해석 |
|---|---:|---:|---|
| 검색 반영 | 46/50 (92%) | 45/50 (90%) | 두 프롬프트 모두 RAG 반영에는 강점 |
| 인용 표시 | 46/50 (92%) | 45/50 (90%) | 표시 자체는 높지만 문장별 귀속 검증은 별도 과제 |
| 정확도* | 5/10 (50%) | 3/10 (30%) | 둘 다 목표 90%에 미달 |
| 할루시네이션율* | 5/10 (50%) | 4/10 (40%) | 둘 다 목표 3%를 크게 초과 |
| Critical | 3건 | 4건 | 출시 기준 0건을 충족하지 못함 |
| 평균 응답 길이 | 553자 | 442자 | 압축은 03이 유리하지만 안전 행동 일부가 누락됨 |

\* 골든 답안이 있는 10문항 기준이다.

같은 8문항·같은 RAG·같은 모델에서 프롬프트만 D에서 E로 바꾼 통제 실험은 검색 반영을 0/8에서 5/8(62.5%)로 높였다. 이는 프롬프트가 검색 결과를 답변에 반영하는 데 기여했다는 근거다. 반면 E와 03의 정확도·할루시네이션 결과는 표본이 10문항이고, v5 미실행 상태이므로 v5의 성능 예측으로 사용하면 안 된다.

## v5가 직접 보완한 실패 모드

| 과거 실패 | v5 보완 | 사전 판정 |
|---|---|---|
| `교제축복`, `천애축승`처럼 확인되지 않는 명칭을 비슷한 용어로 바꾼 뒤 절차·수치를 생성 | 정확한 RAG 확인 없이는 자동 보정·관련 절차 보충을 모두 금지 | 지시 수준 보완 완료, 런타임 미검증 |
| `하나님`, `2세` 등 구용어가 답변에 노출 | 사용자 표기는 존중하되 출력 용어를 `하늘부모님`, `축복자녀`로 통일 | 지시 수준 보완 완료, RAG 원문·후처리 검증 필요 |
| 압축된 위기 지시에서 혼자 여부와 위험 수단 거리두기가 빠짐 | 위기 응답을 1~4단계의 순차 규칙으로 분리 | 지시 수준 보완 완료, 런타임 미검증 |
| 모델이 실행마다 다른 위기 전화번호를 자체 지식으로 생성 | 위기 자원을 운영 설정에서만 사용하도록 제한 | **운영 설정 주입이 구현되기 전에는 미완료** |
| 개인 상황을 추정하거나 자격을 판정 | 공통 정보 우선, 맥락 카드, 개인 자격·승인·탈락 판정 금지 | 카드 API와 회귀 검증 필요 |

## 출시를 막는 구조적 과제

1. **빈 검색과 미검증 용어를 코드에서 차단해야 합니다.** 과거 세 프롬프트 모두 “확인되지 않는다”고 말한 뒤 일반 절차를 생성했습니다. 검색 점수·문서 존재·정확한 용어 일치를 확인하는 정책 계층 없이는 프롬프트만으로 막을 수 없습니다.
2. **위기 자원은 버전 관리되는 운영 설정이어야 합니다.** 프롬프트에 고정된 번호나 모델의 일반 지식은 지역·변경·검증 문제를 남깁니다. 응답 생성 시 최신 설정을 별도로 주입해야 합니다.
3. **맥락 카드는 텍스트 후속 질문이 아니라 구조화된 UI·API가 필요합니다.** 현행 후속 질문 칩은 선택 값을 안정적으로 보내지 못합니다. 카드 키, `잘 모르겠어요`, 직접 입력, 건너뛰기 처리가 필요합니다.
4. **출처는 우선 `참고 자료`로 표시해야 합니다.** 현재 인용이 답변 문장과 정확히 귀속되는지의 검증이 완료되기 전에는 `근거`라고 단정하면 안 됩니다.
5. **RAG 코퍼스 운영이 필요합니다.** 승인자·문서 유형·발행/개정일·적용 범위가 없는 자료는 최신성 우선순위를 결정할 수 없습니다. 가정생활의 해결 조언은 승인된 자료가 추가되기 전까지 제공 범위에서 제외합니다.

## 권고 순서

1. v5 프롬프트와 사용자 플로우를 디자인 초안으로 검토한다.
2. 빈 검색·미검증 용어 폴백, 위기 자원 설정, 맥락 카드 API, 참고 자료 라벨을 제품 계층에 구현한다.
3. 같은 50문항 환경에서 v5를 실행하고, 최소한 기존 10개 골든 문항과 위기·보안·범위 밖 문항을 재채점한다.
4. `Critical 0건`, 정확도와 할루시네이션 기준 충족, 위기 단계 누락 0건을 확인한 뒤에만 운영 적용 여부를 결정한다.

## Validation Report

### Overall Assessment: Needs revision

v5는 기존 결과에서 확인된 프롬프트 결함을 직접 겨냥했지만, 실제 생성 결과가 없으므로 효과를 주장할 수 없다. 특히 빈 검색·용어 일치·위기 자원·카드 전달은 시스템 프롬프트 외부의 구현 의존성이므로, 현재 상태는 **설계 검토 통과 / 운영 배포 보류**가 적절하다.

### Methodology Review

- 비교 수치는 2026-07-29의 두 회귀 보고서에서 그대로 가져왔다.
- E와 03은 같은 테스트 봇·모델·50문항을 사용했으나, 정확도와 할루시네이션은 골든이 있는 10문항만 채점됐다.
- E와 라이브 D의 전체 비교는 프롬프트·모델·RAG 문서 집합이 함께 달라져 인과 비교가 아니다. 8문항 통제 실험만 프롬프트 효과의 직접 근거다.
- v5는 위 과거 결과를 바탕으로 한 정적 검토 대상이며, 현 시점에 성능 수치가 없다.

### Required Caveats for Stakeholders

- 이 문서는 v5의 런타임 평가 결과가 아니다.
- 50문항 중 40문항은 과거 보고서에서도 정확도·할루시네이션 채점이 완료되지 않았다.
- `참고 자료` 표시는 문서 수준의 신뢰 신호이며, 문장별 사실성 보증이 아니다.
