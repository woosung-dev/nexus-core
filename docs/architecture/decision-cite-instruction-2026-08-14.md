## 1. ⚠ 병렬 세션 사고 — 라이브가 5분간 어긋났다

| 시각 | 무슨 일 |
|---|---|
| 17:29 | **세션 A** 가 인용 지시를 채택하고 라이브 봇 11 을 1,481자로 올림 → `dc2affe` 커밋 |
| 17:44 | **세션 B**(이 세션)가 라이브 프롬프트가 바뀐 것을 발견. 커밋을 아직 못 봄 |
| 17:50 | 세션 B 가 「기준 미달」로 판단해 라이브·로컬을 **1,341자로 되돌림** |
| 17:53 | 세션 B 가 `dc2affe`·`ac3d5d1` 커밋을 발견 → 판단 철회 |
| 17:55 | **1,481자로 복원.** 커밋과 라이브가 다시 일치 |

**세션 B 가 왜 헛짚었나** — 세 가지가 겹쳤다.

1. **`bots.updated_at` 이 안 움직인다.** psql/스크립트로 직접 UPDATE 하면 SQLAlchemy 의
   `onupdate=func.now()`(`app/models/bot.py:65-71`)를 안 탄다. 라이브가 방금 바뀌었는데
   타임스탬프는 `2026-08-12 14:22` 그대로였다 → 「정체 불명의 변경」으로 보였다.
2. **`git log` 를 세션 시작 때 한 번만 봤다.** 그 사이 커밋 2개가 올라왔다.
3. **인계문서 본문이 세션 중에 바뀌었다.** 세션 B 가 읽은 것은 251줄판, 판정 시점은 315줄판이었다.

> **교훈 — 병렬 세션이 돌 때는:**
> - 라이브 DB 를 고치기 **전에** `git log -3` 을 다시 봐라. 세션 시작 때 본 것으로 믿지 마라
> - 라이브 `bots` 를 psql 로 고치면 **변경 이력이 아무 데도 안 남는다.** 관리자 화면(ORM)으로
>   바꾸거나, 직접 고쳤으면 여기 같은 메모를 반드시 남겨라
> - 인계문서가 세션 중에 바뀔 수 있다. 판정 직전에 다시 읽어라

## 3. `dc2affe` 가 보고하지 않은 지표 ② — `_SELF_REFUSAL_RE` 에 구멍이 있다

`app/services/unanswered.py:120-131` 의 자가 이 문장을 **못 잡는다.**

```
본 규정집에 상세히 명시되어 있지 않아 본 답변에서 확정하기 어렵습니다.
```

- 패턴 `규정집에\s*(?:는\s*)?(?:없|나와\s*있지\s*않|명시되지\s*않)` 은 「규정집에」 **바로 뒤**를 보는데
  실물에는 「상세히」가 끼어 있다
- 뒤쪽 대안 `명시된\s*(?:내용|문서|조항|규정)…` 도 「명시**되어** 있지 않아」와 어긋난다

**영향**: 봇이 제대로 유보한 턴이 「유보 안 함」으로 집계된다. **유보율이 실제보다 낮게 보고된다.**
위 §2 의 후퇴 3셀 중 1셀이 정확히 이것이다.

**고칠지 여부는 사용자 결정이다** — 채점 기준을 건드리는 일이다. 넓히면 오탐(정상 답변을 유보로
세는 것)이 는다. `strict_mode._REFUSAL_RE` 가 `.{0,16}` 로 느슨하게 잡다가 오탐을 낸 이력이
정확히 그 반대편 사고다. **두 자는 다른 자다. 재사용 금지.**

## 4. ✅ 2026-08-15 — ③ 의 정의가 바뀌었고, 이 실험은 목표를 달성했다

**사용자 결정: `③ 과잉 거절` 에서 「지어냄」을 뺀다.** 게이트가 옳게 막은 것을 「과잉」이라 부르는 게
이름이 틀린 것이었다. 지어냄은 **`④ 지어냄률` 로 따로 센다** — 둘은 고치는 곳이 다르다
(③ = 게이트/프롬프트, ④ = 모델/생성). 섞으면 ③ 이 **구조적으로 도달 불가능**해진다.

`_kpi.py` 에 반영했다. 새 정의로 재면:

| 지표 | 목표 | 전 `s1_lex_0813` | 후 `cite_0814` = 라이브 현행 |
|---|---|---:|---:|
| ③ 과잉 거절 (지어냄 제외) | ≤5% | 10.6% (7/66) | **1.5% (1/66)** ✅ |
| ④ **지어냄률** (신설) | 미정 | 23.6% (26/110) | **20.4% (22/108)** |

> ⛔ **2026-08-18 정정 — `④ 20.4%` 는 사실이 아니다.** 판정 코드가 프롬프트의
> `# 참고 정리`(위키 페이지) 채널을 안 봐서 **정확한 인용을 「지어냄」으로 셌다.**
> replay 600건 재판정에서 57건 → 1건, 그 1건도 오탐 — **실제 지어냄 0건**이다.
> 근거와 경위: `next-session-gate-overblock-2026-08-15.md` §5 · PR #72 · #74.

**이 실험은 ③ 목표를 달성했다.** 프롬프트로 고칠 수 있던 몫은 사실상 전부 사라졌다.
→ **인용 지시로 더 짜낼 것은 없다.**

### 대신 ④ 가 드러났다 — 다음 우선순위 후보다

**5턴 중 1턴이 주입 밖 근거를 댄다.** 지금은 게이트가 막아 ①(유해 확답)이 0건이지만
**게이트가 유일한 방어선**이다. 게이트가 없거나 무보호 경로(`file_search`)로 빠지면 그대로 나간다.

④ 의 목표치는 아직 안 정했다. 정하려면 사용자에게 물어라.
「어휘 매칭으로 근거 사용을 판정」은 **3전 3패** 이력이 있으니 그 이력부터 읽어라.
