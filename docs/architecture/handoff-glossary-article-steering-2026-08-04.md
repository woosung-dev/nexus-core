## 0. 30초 요약

축복 봇이 케이스별로 갈려야 할 답을 뭉갠다. 선행 세션이 원인을 **검색**으로 좁혔다 —
분기 근거는 문서에 있는데 사용자가 분기축을 말로 꺼내지 않으면 그 청크가 top_k 에 못 들어온다.

해법 가설: **용어집이 가진 `근거 조문` 포인터로 검색 쿼리를 확장한다.**

이 가설의 **하류 절반은 이미 검증됐다.** 그러나 **상류 절반이 미검증이고, 거기서 문제가 발견됐다.**
이 세션은 상류를 판정한다.

## 2. ⚠️ 이 세션이 판정할 것 — 상류가 뚫려 있다

**위 스모크는 확장어를 사람이 손으로 넣었다.** 답을 알고 넣은 것이라 파이프라인 검증이 아니다.

147개 용어·별칭으로 **어휘 매칭**을 10문항에 돌리면:

```
R-219  "나는 2세고 1세와 올해 축복을 받을거야. 축복 받고 나서 해야되는 의식이…"
       → 매칭 0건
```

질문에 `축복자녀가정 편성`도 `12일 가정출발의식`도 없다. **사용자가 그 용어를 쓰지 않는 것이
애초의 문제**였으므로, 표면 문자열 매칭으로는 도달할 수 없다.

10문항 어휘 매칭 실측: **A-93 · B-114 · R-219 = 0건**, 나머지 7건은 1~3건.

> 즉 "용어집 조문으로 검색을 유도한다"는 안은 **하류는 되는데 상류가 안 된다.**
> **이 세션의 유일한 질문: 질문에서 옳은 조문에 도달할 수 있는가.**

## 3. 실험 설계

### 팔 3개 (봇 11, 페르소나 유지, `metadata_filter="bot_id = 11"` 현행 그대로)

변수는 **쿼리 확장 방식 하나**뿐이다. 필터·프롬프트·모델을 바꾸지 않는다.

| 팔 | 쿼리 | 매핑 비용 |
| --- | --- | --- |
| **P** 대조 | 원 질문 그대로 | 0 |
| **M1** 어휘 | 원 질문 + (147 용어·별칭 최장일치로 얻은 표준용어·조문) | API 0회 |
| **M2** 닫힌어휘 | 원 질문 + (147개 enum LLM 매핑으로 얻은 표준용어·조문) | API 1회 |

**M2 매핑 호출 규격**
- 페르소나 **없음** (페르소나는 판정을 왜곡한다 — §1 실측)
- File Search **끄고** 순수 분류로 호출한다(147개 목록을 프롬프트에 직접 넣는다, 2,695자)
- 출력은 **147개 중 선택**만 허용. 목록에 없는 용어를 만들면 폐기하고 재시도.
- 이건 CLAMBER 가 어렵다고 한 *판정*이 아니라 닫힌 어휘 *추출*이다 — PR #51 이 실패한
  5-way route 판정과 다른 종류의 과제다.

### 확장 쿼리 조립 (M1·M2 공통)

```
확장쿼리 = 원질문 + " " + 표준용어들 + " " + 조문번호들
```
- 매핑 결과 **상한 6개 용어**. 조문은 중복 제거.
- `source_articles` 가 빈 용어는 확장에서 제외(조문이 없으면 유도 효과가 없다).
- 매칭 0건이면 **확장하지 않고 원 질문 그대로** 보낸다(= P 와 동일. 그 사실을 기록한다).

### 어휘 매칭 규칙 (M1) — 선행 세션에서 확정

- NFKC + casefold 후 부분문자열, **최장일치** 우선
- 2자 이하 표기 제외
- **충돌 표기 5건 제외**: `교회`↔`현장교회`, `확정자`↔`축복식 확정자`, `중도문제`(경도문제/중도문제)
- 일반어 스톱리스트: `축복 성별 은사 헌금 후보자 해원 환불` — 거의 모든 질문에 걸려 잡음이 된다

### 규모

10문항 × 3팔 × 2회 = 60 호출 + M2 매핑 10문항 × 2회 = 20 호출 = **약 80 호출, 50분**

## 5. 판정 기준

### 1차 — 상류 (이 세션의 핵심)

문항별로 기록한다.

```
M1 매핑 결과 (용어·조문)      M2 매핑 결과 (용어·조문)
→ 그 조문이 이 질문의 정답 근거인가   (사람 Y/N)
→ M1·M2 가 서로 일치하는가
```

| 관측 | 결론 |
| --- | --- |
| M2 가 10문항 중 8건 이상에서 옳은 조문 도달 | **상류 성립. 구현 진행** |
| M2 가 5~7건 | 조건부 — 어느 유형에서 실패했는지 보고 범위를 좁힌다 |
| M2 가 4건 이하, 또는 반복 간 흔들림이 큼 | **상류 불가. 이 로드맵 전체를 접는다** |
| M1 ≈ M2 | 어휘 매칭으로 충분 → LLM 호출 불필요(더 좋다) |

### 2차 — 하류 (확인 사살)

`_branches.py` 를 그대로 돌려 팔별 분기 수·미근거 조건을 잰다.
**특히 R-219 에서 p.21 이 회수되는지**를 문항별로 본다.

| 관측 | 결론 |
| --- | --- |
| 확장 팔에서 분기 수 증가 **AND** 미근거 조건 증가 없음 | 개입 성공 |
| 분기는 늘었는데 미근거 조건도 늘어남 | 확장이 엉뚱한 조문을 끌어옴 → 상한·스톱리스트 재조정 |
| 변화 없음 | 하류 스모크가 우연이었을 가능성 → 재검토 |

## 7. 주의사항

- **라이브 호출이다.** 실 Gemini 비용 발생, 실 봇 문서를 읽는다.
- **Gemini free-tier 는 모델당 하루 500회.** `gemini-3.5-flash-lite`(봇11 설정 모델)는
  선행 세션 당일 소진됐다. `gemini-3.1-flash-lite` 로 고정하고, 팔 사이에 바꾸지 않는다.
- **읽기 전용.** DB 는 `SELECT` 만. 실행 전후 `messages`·`chat_sessions` 카운트와
  `bots.system_prompt` 해시를 대조해 증명한다.
- **`bots.system_prompt` 수정 금지.** 확장은 사용자 메시지 쪽에만 적용한다.
- **같은 조건 최소 2회.** 1회로 판정하지 않는다.
- **관측을 먼저 기록하고 판정은 그 뒤에.** 가설을 섞지 않는다.
- 산출물은 `exports/` 아래(gitignore).
