## 1. 게이트 교체 — 이것부터 하지 않으면 STEP 1이 「퇴보」로 보인다

지금 게이트 「정확도 ≥ 90%」는 doc_gap 73%에서 **구조적으로 도달 불가**다. 폐기한다.

| 새 지표 | 지금 | 목표 | 뜻 |
|---|---:|---:|---|
| **유해 확답** | 팔당 1~3건 | **0건** | 근거 없이 단정한 답. 사고다 |
| **유보율**(문서없음 문항) | 46.9% | **≥ 95%** | 모를 때 모른다고 하는 비율 |
| **과잉 거절** | 5.0% (봇 29 실측) | **≤ 5% 유지** | 답할 수 있는데 안 답함. **B의 유일한 위험** |
| (보조) 답 있는 문항 정확도 | 63.5% | 유지 | 떨어지면 STEP 1 롤백 |

> ⚠ **strict 게이트를 켜면 헤드라인 정확도는 내려간다.** 유보가 늘기 때문이다.
> 그건 실패가 아니라 설계다. **게이트를 먼저 바꿔 놓지 않으면 스스로를 속이거나, 옳은 일을 하고도 후퇴로 보고하게 된다.**

**자기기만 방지 장치**: 게이트를 바꾼 날 이후 모든 보고에 **옛 자(정확도) 값을 병기**한다. 새 지표만 보고하면 안 된다.

### 이것이 「발전이 안 보인다」의 세 번째 원인이다

1. 자가 흔들린다 (심사 지시문 16.4pp > 프롬프트 7.2pp)
2. 문항의 73%가 doc_gap
3. **피드백 루프가 45문항 오프라인 벤치마크 하나뿐이다** ← 신규

실사용자가 없는 채로 우리가 만든 문항으로만 몇 달을 쟀다.
> Barnett et al. 2024: *"RAG 시스템의 검증은 운영 중에만 가능하다(feasible only during operation)."*

### 따라서 순서의 의미가 바뀐다

```
STEP 1 strict 게이트  ┐
STEP 2 위기 대응      ┘→ 「안전하게 내보낼 수 있다」 = 출시 요건
STEP 3 실제로 내보낸다 → 진짜 질문 유입 → unanswered 축적 → 자료 우선순위가 데이터로
```

STEP 3 은 「화면 가동」이 아니라 **「트래픽 만들기」**로 재정의한다(아래 STEP 3 개정판).

## 0-3. 측정 전 세팅 점검에서 나온 정정 3건 (2026-08-13)

### ✅ FINDINGS §5 는 맞았다 — 한때 「틀렸다」고 적었던 것을 취소한다

한때 이 자리에 「챗봇이 갖고 있지 않은 문서 4종은 절반이 틀렸다」고 적었다. **그것이 틀렸다.**
스토어 전체를 봇이 다 본다고 가정한 오독이었다.

**file_search 는 봇별로 문서를 거른다.**

```python
# app/services/rag/gemini.py:520
metadata_filter=f"bot_id = {bot_id}"
```

새 키 스토어 87건을 `custom_metadata.bot_id` 로 갈라 보면:

```
봇 11 (라이브 주력)   2건 = 규정집 v20 + 대사전 v4     ← FINDINGS 기록과 정확히 일치

봇 29 (측정 대상)     0건  ← 문서가 하나도 배정돼 있지 않았다
```

**스토어에 국제규정집이 있어도 봇 11 은 못 본다.** 다른 봇 앞으로 등록돼 있기 때문이다.
「자료가 없다」와 「이 봇이 그 자료를 안 본다」는 다른 문제라는 관찰 자체는 유효하지만,
봇 11 기준으로는 FINDINGS 가 정확했다.

### 봇 29 file_search 가 항상 빈손이던 이유 — 설정 누락이었다

인용 0건은 `reference_rag_grounding_underreports`(검색은 정상, 보고만 누락)가 아니었다.
**봇 29 앞으로 등록된 문서가 0건**이라 검색이 구조적으로 빈손이었다.

```
before   인용 0건 · direct_citation=False → 「확인되지 않습니다」
after    인용 3건 · direct_citation=True  → 규정집 내용으로 답변
```

`~/Downloads` 에서 원본 2종을 찾아 봇 29 로 재업로드했다. **해시가 봇 11 등록본과 같다.**

```
d8a5ef90e8036df9 · 2,062,334 bytes  규정집 v20
93636bb2855357b6 · 13,867,017 bytes 대사전 v4
```

그리고 이 sha256 앞 8자가 `wiki_bot_sources.sha8` 와 같다 — **위키(lexical) 250유닛이 바로 이
두 PDF 를 쪼갠 것**이다. 두 경로가 같은 원본을 보므로 lexical ↔ file_search 비교가 성립한다.

### ⚠ 스토어에 규정집 버전이 셋 동시에 있다

```
개정초안 2026v15_항목별정리본.pdf
개정초안 2026v19_입회원서규정보완.pdf
개정초안 2026v20_축복자녀간축복보완.pdf   ← 기준 버전
국제 규정집.pdf                          같은 파일이 10회 이상 중복 등록
```

file_search 가 v15·v19 를 뽑으면 **낡은 답이 최신인 척** 나온다. 이번 측정에서는 건드리지
않는다(변수 하나 원칙). **별도 정리 과제**로 남긴다 — 중복 제거 + 낡은 버전 회수.

### ⚠ file_search 는 인용을 보고하지 않는다 (n=3)

```
lexical      주입 4~6건 · 인용 4~6건 · direct_citation=True   → strict 차단 0/3
file_search  주입 -    · 인용 0건   · direct_citation=False  → strict 차단 3/3
```

`reference_rag_grounding_underreports` 가 기록한 그 현상이다. **file_search 경로의 strict 는
`has_direct_citation` 만 보므로, grounding 보고가 누락되면 근거를 실제로 썼어도 차단된다.**
55문항 전수로 확인한다.

strict 를 켜고 실제로 쳐 보니 **차단 문구가 담당자로 넘기지 않았다.**

```
전: 확인 가능한 직접 인용 근거가 없어 이 내용은 답변해 드릴 수 없습니다.
후: 규정집에서 근거를 찾지 못해 답변드리기 어렵습니다.
    담당 교회장님이나 가정행복국(02-3271-0502)으로 연락 부탁드립니다.
```

제품 방향 B 는 「유보하고 **담당자로 넘긴다**」인데 유보만 하고 끊겼다. 유보율 68.2% 라
**10문항 중 7개가 막다른 길**이었다. 「직접 인용 근거」도 내부 용어다. 계약 테스트를 걸었다.

> 오프라인 220셀로는 못 잡았다. 그 측정은 **차단 여부**만 셌지 차단됐을 때 나가는
> 문장을 읽지 않았다. 라이브에 켜고 실제로 쳐 본 것이 잡아냈다.

### ⚠ 프로덕션 Gemini 키는 **구 키 `…ufUU`** 다

`.env` 의 신 키 `…F4lg` 와 다르다. **스토어는 키에 묶이므로 file_search 봇을 새로 만들려면
프로덕션 키 스토어에 올려야 한다.** 프로덕션 키를 신 키로 바꾸면 봇 2~10 의 문서가 전부
안 보이게 된다 — 바꾸지 마라.

봇 11 은 `lexical`(DB 코퍼스)이라 키와 무관하다.

### 비교군은 안 만들었다 (의도)

「봇 11 복제 + file_search」로 1변수 비교를 하려 했으나 보류했다. 근거: 그 비교는 이미
220셀로 쟀고(어휘 유보 68.2% vs 의미 26.4%), 20~30명 2주로는 그보다 정밀해지지 않는다.
게다가 **덜 거절하는 봇이 옆에 있으면 사람이 그쪽으로 몰려** strict 데이터가 안 쌓인다.
필요해지면 그때 붙인다 — 닫히는 문이 아니다.

파일럿 대상자 명단과 안내문. **사용자 결정 필요** — 누구에게, 언제 여는가.

## STEP 1 — strict 게이트 (B의 본체 · 1~2일)

## 함정

1. **`retrieval_mode=file_search` 면 strict 게이트가 사실상 무력하다.** `has_direct_citation()` 은
   어휘 경로에서 항상 참이라 보호가 안 늘어난다. `has_grounded_citation()`(#59)이 그 수리인데
   **어휘 경로 전용**이다. STEP 0 에서 `lexical` 인지 반드시 확인.
2. **`src_id` 만 보면 정답이 죽는다.** 과잉 거절 22.5% → 5.0%. 조문 형식(`제55조`)을 함께 받는 것이 수리의 핵심이다. 이 대조를 좁히지 마라.
3. **검색 점수로 유보를 판정하지 마라. 3전 3패다.** (인용 형광펜 어휘매칭 25% · 관리자 근거상태 라벨 66% · 45문항 네 갈래 전부 실패) 네 번째를 하지 마라.
4. **`unanswered._SELF_REFUSAL_RE` 와 `strict_mode._REFUSAL_RE` 는 다른 자다.** 재사용 금지 — 라이브 문구를 못 잡는다.
5. **「아직 정리되지 않았다」는 약속이다.** 누가 언제 검수하는지 안 정하면 그 문구를 내면 안 된다. 합의 없으면 `UNANSWERED_MESSAGE` 상수를 중립 문구로 바꾼다.
6. 로컬 `bots.id=11` 은 `opus2_v4`(5,608자)로 **다른 봇**. 로컬 D-1 ver2 는 **29번**.
7. Gemini 무료 한도 **모델당 하루 500회**(KST 16:00 리셋). 어휘 경로는 키를 바꾸면 한도가 새로 생긴다.
