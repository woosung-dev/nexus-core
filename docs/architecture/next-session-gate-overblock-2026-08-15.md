## 2-2. 2026-08-18 — 검색(dense)을 실제로 켜서 재 봤다. **답변률은 안 올랐다**

`WIKI_DENSE_SCALES=unit` 으로 replay **150건**(k 상위)을 다시 돌려 `replay_0815` 와 같은 문항끼리
비교했다. 자: `exports/replay_2026-08/_compare.py` (호출 0회).

| | 현행 | dense | |
|---|---:|---:|---|
| 답 받음 | 38.0% (57) | 38.7% (58) | **+0.7%p** |
| 자체 거절 | 39.3% (59) | **33.3% (50)** | **−9** |
| 게이트 차단 | 22.7% (34) | **28.0% (42)** | **+8** |

### 실패가 아니라 **병목이 옮겨간 것**이다

**검색 개선은 실재한다** — 자체 거절이 9건 줄었다. 「교류에 대해 부모님과 의견이 다르다」에
`reg-24`(부모매칭 지도 원칙)가 들어와 답이 나갔고, 「사랑해 애정표현」에서는 `reg-91`(자살 사안)이
빠지고 `reg-66`(탈선·성적문제)이 들어왔다.

**그런데 게이트가 그 이득을 거의 다 먹었다(+8).** 봇이 답을 하기 시작하니 게이트가 걸러냈다.
→ **검색과 게이트는 직렬이다. 한쪽만 고치면 다른 쪽이 먹는다.**

앞의 「게이트 표기 누락은 상한 +4.8%p뿐」은 **현행 검색 기준**의 값이다. 검색이 좋아지면
게이트에 도달하는 턴이 늘어 게이트의 몫이 커진다.

### dense 는 좋은 것도 밀어낸다

```
「3일 금식에 대해서 알려줘」(5명)
  현행 : reg-17 · reg-87 · reg-33 · reg-19  → 답 받음
  dense: reg-33 · glo-4 · reg-48 · reg-89   → 게이트 차단
```

밀려난 `reg-17`·`reg-19` 는 **독립 표본에서 금식 문항의 정답으로 손라벨된 조문**이다.
뒤집힌 문항이 63/150(42%)인데 **좋아짐 26 · 나빠짐 25 로 거의 상쇄된다.**

**다음 가설(미검증)**: 주입 자리가 8칸(`service.BUDGET_UNITS`)뿐이라 BM25 와 dense 가 서로를
밀어낸다. 12로 늘리면 둘 다 들어갈 수 있다 — 상수 한 줄, 검증에 생성 150회.

### ⚠ 과적합을 한 번 잡았다 — 자를 두 개 써라

`_retrieval_ab.py` 로 융합 조합 10가지를 훑어 **「fact 제외 + RRF_K=10」이 9/14 로 최고**였는데,
같은 조합을 **독립 표본**(`exports/wiki_eval/corpus_evidence.json` 손라벨 9건)에 대면 6/9 로
최고가 아니었다(최고는 「현행+dense k=60」 7/9). **내 손으로 만든 정답지 하나로 조합을 고르면
과적합한다.** 이걸 안 잡았으면 잘못된 설정으로 600회를 태웠을 것이다.

> ⚠ **`_retrieval_ab.py` 는 `WikiIndex(11, 파일시스템)` 을 직접 만든다.** 실제 파이프라인은
> `get_index(29)`(DB)다. 유닛은 같지만 **페이지가 다르고, `fact` 스케일은 페이지에서 파생된다.**

`## 사실`)에는 **문자 상한이 전혀 없다**(`_wiki_block`).

```
# 규정 원문 (예산 적용)   중앙값 3,238자 · 유닛 4건
# 참고 정리 (상한 없음)   중앙값 4,374자 · 최대 14,639자
────────────────────────────────────────
합계                     중앙값 7,710자   ← 60문항 실측
```

「자료가 3,000자로 제한돼 4건밖에 못 준다」는 **틀린 설명**이다. 이미 7,700자가 들어가고 있고
절반 이상이 우리가 만든 요약이다. **`BUDGET_CHARS` 를 키우는 방향은 철회했다.**

그리고 이것이 「지어냄」 오탐의 구조적 원인이다 — `## 사실` 에는 `> 원문 인용` 이 붙어 있어
**`units` 에 없는 조문 원문이 모델에게 간다.** PR #71 이 그 기록을 고친다.

## 6. 함정

1. **라이브(Neon)에 쓰지 마라.** `_run_e2e.py:47` 이 DSN 에 `neon.tech` 가 보이면 종료하지만
   `psql`·관리자 화면엔 그 보호가 없다.
2. **라이브 `bots` 를 psql 로 고치면 `updated_at` 이 안 움직인다.** SQLAlchemy 의
   `onupdate=func.now()`(`app/models/bot.py:65-71`)를 안 타기 때문이다. **변경 이력이 아무 데도
   안 남는다.** 2026-08-14 에 병렬 세션 둘이 이것 때문에 라이브 프롬프트를 5분간 어긋나게 만들었다
   (경위: `decision-cite-instruction-2026-08-14.md` §1).
3. **병렬 세션이 돌 수 있다.** 라이브를 고치기 **전에** `git log -3` 을 다시 봐라.
   세션 시작 때 본 것으로 믿지 마라 — 인계문서 본문도 세션 중에 바뀔 수 있다.
4. **호출이 문항 수의 5.65배다.** `_fill_evidence` 가 인용 청크마다 1회
   (`rag/evidence.py:107`, 실측 평균 인용 4.65개). `--no-backfill` 로 끄면 1회다.
   판정은 `trace` 로 하므로 결손 수집에는 영향이 없다. **`--throttle 10` 미만은 그래도 금지.**
5. **검색 점수로 결손을 판정하지 마라. 3전 3패다.**
6. **거대 유닛 함정.** `reg-100`(29,774자)·`reg-3`(8,377자)에는 아무 말이나 다 있다(중앙값 232자).
   「질문의 말이 reg-100 에 있다」는 아무 정보가 아니다.
7. **로컬 `bots.id=11` 은 `opus2_v4` 로 다른 봇이다.** D-1 ver2 는 **29번**.
8. **`unanswered._SELF_REFUSAL_RE` 와 `strict_mode._REFUSAL_RE` 는 다른 자다. 재사용 금지.**
9. **strict 차단 턴은 `unanswered_questions.reason` 에 `self_refusal` 로 들어간다** —
   `STRICT_EVIDENCE_MESSAGE` 자체가 그 정규식에 걸린다. 「게이트가 막음」과 「봇이 스스로 거절함」을
   그 테이블만으로는 못 가른다. 구분은 `messages.trace` 의 `STRICT` 단계로 한다.
