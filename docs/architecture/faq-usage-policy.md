# FAQ 운용 정책 — 차단·회피 전용 (2026-08-11 확정)

> **한 줄: FAQ 에 「정답」을 등록하지 마라. 공격적·악의적 질문을 막는 데만 쓴다.**
>
> 이 규칙은 2026-06-25 에 이미 정해졌는데 **감도 튜닝 메모의 마지막 문단에 묻혀 있어
> 반복해서 잊혔다.** 그래서 코드(`faq_service.py` 모듈 docstring)와 이 문서 두 곳에 박는다.

---

## 1. 규칙

| | |
|---|---|
| ✅ **허용** | 공격·악의적 질문 차단, 회피·확인유도 문구 |
| ❌ **금지** | 사실 답변 치환 (「이 질문엔 이 답」) |
| ❌ **금지** | 「규정집에 답이 없다」는 안내를 FAQ 로 처리하는 것 → `ops_facts` 의 일이다 |

하위 케이스가 많은 토픽(**세대 규정·시점 분기·서류 목록**)에 캔드 정답을 박는 것이
가장 위험하다. 살짝 다른 질문에 발동하면 그대로 오답이다.

---

## 2. 왜 — 구조적 이유

FAQ 가 히트하면 `chat_service` 는 **RAG·운영사실·히스토리를 통째로 건너뛰고**
지정답변을 그대로 반환한다(`source=faq_override`).

```
질문 → FAQ 유사도 ≥ threshold ?
         ├─ 예 → 지정답변 그대로 반환.  RAG 안 돌린다. 근거도 없다. 끝.
         └─ 아니오 → 운영사실 → 검색 → 생성 → 근거 검증 → …
```

**near-miss 가 그냥 「덜 좋은 답」이 아니라 「근거 없는 답」이 되는 이유가 이것이다.**
반면 `ops_facts` 는 프롬프트에 얹힐 뿐 검색을 건너뛰지 않는다 — 그래서 같은 사고가
구조적으로 안 난다. **사실을 넣고 싶으면 `ops_facts` 로 가라.**

## 4. 임계값을 올려서 해결되지 않는다

Generator/Evaluator 루프 3라운드(241 probe)로 확정한 결과:

- **양성·음성 유사도 분포가 겹친다(−0.078).** 전역 완벽 분리값이 없다
- per-FAQ 임계값(오라클)은 **같은 데이터 최적화라 과적합** — 홀드아웃에서 붕괴(FP 13)
- 최종 채택 = 관대 per-FAQ + **정서·위기 조언 8종은 0.95 안전 플로어**
  (데이터와 무관하게 높게 잡는다. in-sample 지표가 안전 누수를 놓쳤기 때문)

**즉 감도 조정은 완화책이지 해결책이 아니다.** 그래서 용도 자체를 차단으로 좁힌다.

## 6. 그래서 「못 답하는 질문」은 어디서 처리하나

```
공격·악의적 질문        → FAQ (차단)                    ← 이 문서
규정집에 답이 없다       → ops_facts (운영 사실)          ← RAG 를 안 건너뛴다
답은 있는데 경우가 갈린다 → 재질문 (clarification)
틀린 말을 한다          → retrieval_mode = lexical
```
