## 4. 함정 (물려본 것)

- **하루 한도 500회.** 이번 세션에 429 를 맞았다. **위키(lexical)는 File Search 스토어를
  안 쓰므로 API 키를 바꾸면 한도가 새로 생긴다.** RAG(file_search)는 스토어가 그 키의
  프로젝트에 묶여 있어 키를 못 바꾼다.
- **`_l3.py` 는 resume 이 없다.** 중간에 죽으면 그 팔은 처음부터다. 4팔 순차 = 2~3시간.
- **`_l2.py` 는 `ops_facts` 를 못 읽으면 하드 종료**한다. 로컬 DB 로 돌려라(라이브엔 0행).
- **태그 재사용 = resume.** 조건을 바꾸면 반드시 새 태그. 안 그러면 옛 결과가 섞인다.
- **`_run.py` 는 `chat_service` 를 우회**한다. `--retrieval-mode` 를 안 주면 봇 저장값을 따른다.
- **RAG 4회는 8/05(1·2회차)와 8/11(3·4회차)에 나뉘어 돌았다.** 6일 간격이라 주 비교에서는
  3·4회차만 쓴다. 8/05 분을 섞으면 서비스방향 A 의 할루시가 4.5% → 11.8% 로 보인다.
