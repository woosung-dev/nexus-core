## 순서

① **브라우저 E2E 1회** ← 이게 먼저다. 이 세션에서 유일하게 못 한 것이다
   로컬 봇 29 에 「2세 가정 12일 가정출발의식 절차가 뭐야?」를 묻고 확인할 것:
   - 선택지 카드가 뜨는가
   - 「독신 축복」을 고르면 재질의를 **안 보내고** 「정리 중」 문구가 뜨는가
   - 다른 선택지를 고르면 재답변이 오는가
   - **새로고침해도 카드가 남는가** ← `messages.clarification` 영속화가 이걸 위해 있다
   실 로그인 세션이 필요하다. 자격증명은 사용자에게 물어라

② **`judge_answerability` 에 타임아웃을 넣는다** — 라이브 선행 조건이다
   Gemini SDK 호출에 클라이언트 타임아웃이 없어 2026-08-10 측정에서 12분간 매달렸다
   (네트워크는 정상이었다). 하네스에는 `JUDGE_TIMEOUT_SEC=90` 을 넣었지만
   **프로덕션 경로에는 없다.** 되묻기는 사용자 응답 경로에 있으므로 그대로 켜면 안 된다

③ **#45(`b4u-tier`) 슬롯을 사용자에게 확인받는다**
   질문 4개 상한에 걸려 이것만 규정 근거로만 정했다(제26조 표 · 제25조 ④⑤).
   나머지 3개 규칙의 슬롯은 사용자가 확정한 것이다

④ **라이브 반영** — §0 의 선행 조건 2가지를 채운 뒤
   1. 마이그레이션 `a1c7d3e9f204`(`messages.clarification`)를 라이브에 올린다.
      **없으면 되문 턴을 저장하다 죽는다**
   2. 규칙을 라이브 봇 11에 넣는다. **관리자 API 로는 안 된다** — `validate_active_policy`
      가 봇의 File Search 스토어에 있는 `document_id` 를 요구하는데 봇 11은 `lexical` 이다
   3. `clarify_enabled=true`

⑤ **`min_score` 재스윕** (여유 있으면)

## 제약

- **판정기(`clarification_trigger.py`)를 다시 설계하지 마라.** 45문항으로 보정된 것이다
- **되묻기 삽입은 strict 게이트 뒤여야 한다.** 앞에 놓으면 `_strict_blocks` 가 참이 되어
  봇이 되물은 질문이 `STRICT_EVIDENCE_MESSAGE` 로 치환된다.
  `test_clarification_must_come_after_the_strict_gate` 가 그 사실을 실행으로 남겨 뒀다
- **strict 게이트(PR #59)와 같은 배포에 넣지 마라.** CI 가 테스트를 안 돌리고 main push 가
  곧 배포라, 문제가 났을 때 어느 쪽 때문인지 못 가른다
- **라이브 DB 는 읽기만.** 로컬 검증용 복제봇이 봇 29 다
- **규정집이 안 다루는 갈래는 지우지 말고 `unresolved` 로 표시해라.** 지우면 공백이
  화면에서 숨는다. 새 규칙·선택지를 넣을 때마다 codex 감사를 다시 돌려라 —
  **어휘 카운트로는 공백을 못 찾는다**(「기성」 37건 · 「독신 축복」 17건으로 멀쩡히 뜬다)

## 함정 (인계 §3 에 확인 명령과 함께 있다)

1. 관리자 「테스트하기」는 **LLM 경로**다. 배선이 쓰는 BM25 와 다른 규칙 선택기라
   검증 수단이 안 된다. `tests/test_clarification_policy_v2.py` 를 써라
2. `exports/` 는 gitignore 지만 하네스 `.py` 는 추적된다. **데이터는 이 기계에만 있다**
3. `results.json`·`answers.json` 이 남아 있으면 재측정이 옛 값을 물고 간다.
   `--retry-failed` 가 전부 건너뛰고, 옛 분기 셀이 감사에 섞인다
4. 판정기 자체가 실행마다 흔들린다 — 양성 집합이 6건 ↔ 7건으로 바뀐다
