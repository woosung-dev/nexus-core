# 종합: 3안 지시서 (06·07·08 조사 + 기존 01~05 계승)

작성 2026-08-06. 이 파일이 3안 빌드의 조사 반영 기준이다. 하드룰은 `_brief-common.md`,
목데이터는 `_content.md` — 이 파일은 그 위에 얹는 **조사 유래 결정**만 담는다.

## 조사가 수렴한 결정 (3안 공통)

1. **로스터 형태는 제품이 파는 것이 결정한다** (그리드=콘텐츠 소비 / 리스트=도구 카탈로그 /
   피드=관계 몰입). 우리는 "여러 봇 중 지금 필요한 걸 훑어보고 고른다"가 핵심 행위 —
   피드형 금지, 그리드·리스트는 안별 정체성에 맞게 선택. (06 §2-1)
2. **카드 숫자 배지는 "문서 N종" 하나만.** NotebookLM 소스 수 배지가 유일한 이식 가치 패턴 —
   대화수·좋아요·랭킹은 데이터도 없고 보완재 관계라 논리도 성립 안 함(전면 폐기). 우상단
   상태 배지 1종(예: 신규)까지만 허용. 한 카드 배지 3종 과적재 금지. (06 §3, 07 §4-2)
3. **채팅 진입은 1클릭** (Poe 문법). 지표 없는 우리는 크랙식 상세 모달을 끼울 이유가 약함.
   대신 **채팅 헤더에 봇 프로필 요약 상시 노출**(이름·한 줄 역할·속성 배지·문서 N종) —
   봇을 오가는 사용자가 "지금 어느 봇인지" 잊지 않게. (06 §3)
4. **인용 마커는 레이어 진입점이다.** 각주 [1] 클릭 → 인용 카드 포커스(기존) 위에,
   **호버 팝오버(발췌 1~2줄)** 를 얕은 층으로 추가(Perplexity 3단 깊이의 축소 적용).
   인용 그룹 카드에 **문서 한 줄 요약** 동반(NotebookLM 보강). 파비콘 칩 압축(+N)은
   금지 — 소수 정본 코퍼스는 문서명을 그대로 보여주는 게 신뢰. (07 §3-1·§4)
5. **우리 형광펜 조합(그룹+페이지+하이라이트+각주+정직 라벨)을 전부 갖춘 상용 제품은 없다.**
   이건 지킬 자산이자 차별화 축 — 채팅 뷰에서 이 조합을 실물로 최대한 정성껏 렌더할 것.
   업계 공백이므로 "어디서 본 듯한" 처리로 타협하지 말 것. (07 §4-1, 08 §3)
6. **아바타는 스퀴클 + 저채도.** 실측 3사(Poe 30%·크랙 12px·제타 상단만)가 전부 원형이
   아님. 시드 hue는 순색 금지 — Poe처럼 그레이가 20~30% 섞인 저채도로 눌러야 여러 개
   나열돼도 조용하다. (08 §3)
7. **니어블랙 잉크 실증**: 실측 6곳 전부 #0d~#21 대역(순검정 0곳). 기존 토큰 유지 확정. (08 §1.4)
8. **다단 워크스페이스 금지.** 소스/채팅/스튜디오 3열은 생산성 도구 문법 — 우리 도메인
   (정서적 안전감)에선 채팅이 절대 주인공, 패널은 부른 만큼만. (07 §5-1)
9. **세그먼트형 응답 블록 권장** — 질문·답변을 스캔 가능한 블록으로, 인용을 답변에
   종속시키기 가장 좋은 구조. (08 §2-9)

## 슬롭 블랙리스트 보강 (조사 유래 — 기존 목록에 추가)

- "안녕 ○○님, 오늘 무엇을 도와드릴까요" 개인화 인사 히어로 **문구 그대로**(재유포 템플릿 클리셰.
  개인화 자체는 유효 — 표현을 반드시 새로 쓸 것)
- 글로우 그라디언트 오브/블롭(AI 의인화 구체) · 휴대폰 여러 대 보라 목업 구도
- 얇은 라인 제네릭 아이콘 세트로 카드 채우기
- 세로 포스터(트레이딩카드) 크롭 + 이미지 위 텍스트 오버레이 카드 — 기하학 아바타와 대비
  예측 불가, 롤플레이 톤 (06 §3 버림, 08 §2-4)
- 신뢰도 배지 strong/mixed/weak 류 학술 어휘 — 상담 상황에서 불안 조장 (07 §5-4)
- 관리 콘솔 어휘(Usage·Channels·활성화/비활성화 로그체)가 사용자 화면에 노출

## 안별 지시

### A `a-consumer.html` — 소비자 캐릭터 앱 셸 (ui-ux-pro-max)
- 셸 골격: **상단바 내비**(로고+검색+프로필) + 카테고리 칩 행 — 크랙·제타의 그리드 문법을
  프리미엄으로 정련. 로스터는 카드 그리드(모바일 2열→데스크톱 4열 반응형 실증 패턴).
- 카드: 크랙식 **아바타(정사각 스퀴클)+화이트 여백 텍스트 분리**(오버레이 금지). 이름 볼드·
  1~2줄 설명·태그 칩·"문서 N종" 배지.
- 랜딩: 브라우즈형(크랙 문법 — 콘텐츠를 가리지 않는 로그인 유도) 또는 소개+진입. SSO 카드는
  비침해적으로.
- 액센트: **코랄/오렌지 대역**(뤼튼 #F54211~크랙 #FF5250 실증권, 또는 당근 #FF6600).
  보라 금지. 라이트 기본. 배경은 절대 물들이지 않기 — 버튼·포커스에만.
- 온기는 카피와 아바타 컬러에서: 캐릭터성 과장(포스터 카드) 없이 소비자 앱답게.

### B `b-doctool.html` — 문서 도구 셸 (frontend-design)
- 셸 골격: **좌측 레일**(리스트 중심 탐색과 상관 — Talkie·Poe 데스크톱 문법) 또는 절제된
  상단바 중 선택. 로스터는 **리스트형**(Poe Explore: 행=아바타+볼드 이름+1줄 설명+배지,
  행 클릭=즉시 대화) 우선 검토.
- 잉크·표면: 니어블랙 표준을 가장 엄격하게(#1a1c20~#212529 급 잉크 + 흰 배경), 정보 위계는
  그레이스케일 4~5단으로. 액센트 **파랑 1색**(토스 #3182F6 실증권) — 상태·포커스에만.
- 채팅: 세그먼트형 응답 블록 + 인용을 1급 시민으로 — 각주 위첨자, 하단 "참고한 자료" 서브블록,
  형광펜 하이라이트를 이 안에서 가장 정밀하게. 호버 팝오버 포함.
- 도구의 차가움이 온기를 죽이는 함정(07 §5) 주의 — 시스템 로그체 카피 금지, 해요체 유지.

### C `c-hybrid.html` — 하이브리드 프리미엄 (taste-skill)
- 소비자 온기 × 문서 신뢰의 결합이 명제. 무드 재량이되 조사 힌트:
  - 타이포 차별화가 프리미엄의 지름길(토스·c.ai 모두 자체 폰트로 이탈) — 웹폰트 범위에서
    **400↔700/800 극단 점프 + 크기 대비**로 유사 효과. 중간 웨이트 완전 배제.
  - 다크 니어블랙(#151516급) + 저채도 액센트 = "캐주얼 앱과 다르다" 신호 최속. 또는 웜 라이트.
    (다크 채택 시 명도 위계 등가 유지)
  - 비대칭 배치: 대표 봇 카드 1장만 크게(4:5 정도) "아트디렉션된 한 장"으로, 나머지는 절제 —
    균일 그리드 금지 원칙과 정합. 단 은유 하드코딩 금지 원칙 안에서(콘텐츠 레벨 강조일 뿐
    레이아웃 서사 금지).
- 로스터는 그리드/리스트 자유. 인용 조합은 A·B와 같은 데이터로, 무드만 다르게.
