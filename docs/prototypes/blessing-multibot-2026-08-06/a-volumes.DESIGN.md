# 권 (The Volumes)

## Overview

**명제: 봇을 고르지 말고 표제어를 골라라. 담당 권은 색인이 안다.**

기준본 `blessing-nav-r2-2026-08-05/a-register.html` 은 봇 5개를 메인 하단 「담당 색인 5권」
각주로 내려 두었다. 이번 안은 그 각주를 골격으로 올린다. 통합 색인 하나가 14권을 가로지르고,
표제어를 고르면 어느 권이 그 문서를 싣는지 색인이 알려 준다.

봇을 가르는 축은 **표제어**다. 사용자는 "어느 봇에 물어야 하나"를 몰라도 되고, 알 필요도 없다.
찾는 것을 찾으면 담당은 따라온다.

표제어는 세 절로 나뉜다. **규정에 기준이 있는 표제어** 20개는 문서 이름과 쪽수를 갖고 왼쪽에
골드 세로선이 붙는다. **규정으로 답을 내지 않는 표제어** 6개는 근거를 붙이지 않고 세로선이
없다. **어느 권에도 실려 있지 않은 표제어** 3개는 물어볼 수는 있지만 답을 지어내지 않는다고
그 자리에 적는다. 운영 원칙 §2와 §3-D를 색인 층위에서 먼저 지키는 장치다.

## Colors

바탕 `#F8F5FA` 기준 실측 대비: 잉크 12.0:1, 보조 7.1:1, 메타 5.2:1, 액션 8.5:1,
흰 글씨 on 액션 9.2:1. 다크 `#15121B` 기준: 잉크 15.6:1, 보조 7.3:1, 메타 6.3:1, 액션 9.0:1.
형광펜은 라이트 10.5:1, 다크 8.9:1.

**액센트는 바이올렛 하나뿐이다.** 페이지 전체에서 행동을 뜻하는 색은 `act` 하나이고,
초록 `ok` 는 실제 시맨틱 상태에만 나온다. 담당 권 이름에 `act` 를 쓰는 것이 이 안에서
바이올렛이 하는 유일한 새 일이다. 그것이 이 화면에서 유일하게 누를 수 있는 정보이기 때문이다.

**골드는 색이 아니라 뜻이다.** `#C9A227` 은 바탕 대비 2.2:1 이라 글자에 쓸 수 없다.
표제어 왼쪽 2px 세로선, 발췌 왼쪽 2px 세로선, 능력 표기의 근거 관련 항목 왼쪽 2px 세로선.
이 셋에만 쓴다. 글자로 골드가 필요한 자리에는 `#6B5000` (7.0:1) 을 쓴다.

엠블럼은 실제 로고색 `#F8C800` / `#003D84` 를 라이트와 다크 양쪽에서 그대로 유지한다.

## Typography

Paperlogy 가 표시용, Pretendard Variable 이 본문, Geist Mono 가 위치 표기다.

- **매스트헤드** Paperlogy 900. 화면당 한 번. 여기에는 반드시 사실이 들어간다.
  봇 수에 따라 문장이 바뀐다. 14권이면 "외 12종을 14권이 나누어 싣습니다", 1권이면
  "『블레싱 네비게이션』의 색인", 0권이면 "아직 열린 색인이 없습니다".
- **표제어** Pretendard 600 14.5px. 색인의 주인공이다.
- **담당 권(volume)** Pretendard 600 11.5px `act`. 표제어 오른쪽. 이 안에서 새로 생긴 역할이다.
- **위치(locator)** Geist Mono 10.5px. `축복 행정 규정집 2026 · 38` 처럼 문서와 쪽수만.
  모노를 쓰는 이유는 장식이 아니라 숫자 자리가 세로로 맞아야 훑을 수 있기 때문이다.
- 절차 번호는 `counter(s, decimal-leading-zero)` 로 `01 02 03` 이 된다.

이탤릭을 쓰지 않는다. 강조는 같은 패밀리의 굵기로만 만든다.

## Layout

**메인(색인)** `@container app (min-width:900px)` 에서 `1.62fr / minmax(322px,1fr)` 2단.
좌우가 각각 독립 스크롤이다. 900px 미만에서는 1단이 되고 발췌는 선택한 행 **바로 아래**로
펼쳐진다. 별도 화면이나 모달로 보내지 않는다. 색인에서 항목을 짚으면 그 자리에서 읽는 것이
책의 동작이기 때문이다.

**색인 행** 620px 이상에서 `minmax(0,1fr) auto` 2열이고 세 요소를 명시 배치한다.
자동배치에 맡기면 주석이 우측 열로 튄다. 표제어와 주석이 1열, 담당 권과 위치가 2열 우측 정렬.

**대화** `@container app (min-width:940px)` 에서 `minmax(0,1fr) / 320px`. **무거운 열이 오른쪽이다.**
근거 패널이 항상 열려 있다. B안(근거가 답변 아래 인라인)과 C안(각주를 눌러야 펼쳐짐)의
의도적 대비다. 회색조로 바꿔도 세 안이 구분되어야 한다.

**프로토타입 크롬** 은 좌측 188px 세로 탭. 1100px 미만에서 사라지고 우하단 플로팅 버튼으로
열린다. 크롬이 사라질 때 폭을 온전히 돌려주므로 390px 문서에서 앱이 진짜 390px 로 렌더된다.

카드와 그림자를 쓰지 않는다. 그룹은 `border-top: 1px solid var(--ink)` 로 절을 열고
`border-bottom: 1px solid var(--rule)` 로 행을 나눈다. 한 행에 위아래 선을 함께 두지 않는다.

## Elevation

**평면이다.** 앱 프레임 바깥의 창 그림자 하나를 빼면 그림자가 없다.
깊이는 표면색(`paper` / `surface` / `surface-2`)과 규칙선으로만 표현한다.
선택 상태는 그림자가 아니라 `act-soft` 배경으로 나타낸다.

## Shapes

- **0px** 색인 행, 규칙선, 절 구분, 발췌 본문. 색인은 각져야 색인으로 읽힌다.
- **8px** 버튼, 입력, 담당 권 카드, 데모 상자.
- **999px** 칩과 스위치.

이 셋 밖의 값은 쓰지 않는다.

## Components

### 색인 행 (entry)
`[골드 세로선] 표제어 / 주석 / 담당 권 / 위치` 4요소.
골드 세로선은 `::before` 2×14px 이며 `data-grounded` 가 있을 때만 칠해진다.
담당 권이 둘 이상이면 `블레싱 네비게이션 외 1권` 으로 접는다.
담당 권이 없으면 `data-orphan` 이 붙고 세로선이 사라지며 표제어가 `ink-2` 로 내려간다.

### 발췌 (excerpt)
표제어 / 출처 / 원문 발췌(형광펜) / **이 표제어를 싣는 권** / 함께 보는 표제어.
「이 표제어를 싣는 권」이 이 안에서 새로 생긴 절이다. 권 하나면 버튼 하나, 둘 이상이면
"답의 내용은 같고 다루는 범위가 다릅니다"를 함께 적는다. 40권에서는 셋만 세우고
나머지는 수로 접으면서 "이 규모에서는 소속 교구로 먼저 좁히는 편이 빠릅니다"를 적는다.

### 권 상세 (bot detail)
질문이 "이 권이 무엇인가"가 아니라 **"옆 권과 무엇이 다른가"** 다.
대조 블록 3칸: `이 권만 싣는 문서` / `다른 권과 함께 싣는 문서` (어느 권도 싣는지 명시) /
`이 권이 싣지 않는 문서` (담당 권 지목). 이 권만 가진 문서가 없으면 그렇게 적는다.
그것 자체가 그 권의 자리를 설명한다.

### 능력 표기 (capability)
**규칙: 사용자의 기대와 어긋나는 쪽만 적는다. 기대대로면 아무것도 안 적는다.**

| 실제 설정 | 화면 문구 |
|---|---|
| `history_window: 0` | 앞 대화를 이어서 기억하지 않습니다. 질문 하나에 답 하나씩 드립니다. |
| `evidence_policy_mode: strict` | 문서에서 근거를 찾지 못하면 답하지 않습니다. |
| `use_rag: false` | 문서를 근거로 답하지 않습니다. 결론을 대신 내리지 않고 함께 정리하는 쪽입니다. |
| `is_active: false` | 지금은 답하지 않습니다. 같은 내용을 『…』이 이어받았습니다. |
| `plan_required: PRO` | 카드에는 적지 않는다. 부딪히는 자리에서만 설명한다. |

RAG, strict, legacy, history_window, 시스템 프롬프트, 벡터, 검색 엔진, 내부 분류 이름은
화면에 한 글자도 나오지 않는다(운영 원칙 §6). 14권 중 4권은 표기가 없다.

### 답변 4유형
운영 원칙 §3·§5 를 그대로 렌더한다.

| 유형 | 렌더 | 인용 |
|---|---|---|
| 행정 확답 | 결론(lead) → `근거` → `절차`(01 02 03) → `다음` 순서 고정 | 있음 |
| 맥락 확인 | 공감 → 확인 질문 **정확히 한 개** → 부담 낮은 칩 | 인용 UI 자체가 없음 |
| 근거 없음 | 고정 거절 문장 → 부모님께 여쭐 질문 3개 → 짧은 정서 지지 | 없음 |
| 안전 우선 | 규정 안내 중단 → 안전 확인 → 어른 4단계 → 상담전화 109 | 없음 |

어른 연결 순서는 고정이다. 부모님 → 가정부장님 → 공직자·목회자·사모님 → 신뢰하는 가까운 어른.
안전 우선에서는 피드백 액션 바를 그리지 않는다.

### 이관 (handoff)
**답변 5번째 유형이 아니다.** 답변 4유형은 질문의 성격이 가르고, 이관은 권의 담당 범위가
가른다. 같은 질문도 어느 권에 했느냐에 따라 이관이 되기도 안 되기도 한다.
「근거 없음」의 하위 두 갈래로 둔다.

```
D  문서에서 확인되지 않음
├─ D1  어느 권도 그 문서를 싣지 않는다  → 부모님께 여쭐 질문 3개 (기존)
└─ D2  다른 권이 그 문서를 싣는다      → 그 권을 지목 (이번에 새로 그림)
```

D2 는 봇↔문서 연결을 알아야만 성립한다. 그 값이 없으면 근거 없이 남의 권을 지목하게 되므로
**D1 로 떨어뜨리는 것이 정답이다.** README 선행 과제 1번이다.

A안의 D2 렌더는 **지목한 권의 카드**다. 이름, 문서 수, 왜 그 권인지(문서 이름으로), 능력 표기,
그리고 「그대로 묻기 / 여기서 계속하기」. 옮기기 전에 "질문은 그대로 넘어갑니다. 지금까지의
대화와 근거는 넘어가지 않습니다"를 반드시 적는다.

### 근거 색인 (evidence)
`확인 중` → `참고한 자료 N건` 두 상태를 갖는다. 대기 중에는 스켈레톤이 자리를 잡아
늦게 온 카드가 레이아웃을 밀지 않는다. 백필 실측이 약 15초, 폴링이 2초 × 15회라
이 대기는 없는 상태가 아니라 그려야 하는 상태다.

`approximate` 가 하나라도 있으면 `MessageCitations.tsx` 와 같은 규칙으로 목록 **전체**를
근사로 본다. 라벨이 `참고 가능한 자료 N건` 이 되고, 각주 번호와 형광펜을 어느 카드에도 붙이지
않으며, 고지 문단이 목록 맨 위에 한 번만 놓인다.

`검색되었지만 인용되지 않은 자료` 는 접이식으로 따로 둔다. 인용 0건과 검색 실패는 다른 상태다.

### 피드백
긍정 `정확함 · 도움 됨 · 친절함 · 명확함 · 기타`,
부정 `부정확함 · 도움 안 됨 · 근거 부족 · 너무 김 · 부적절 · 기타`.
`types/api.ts` 의 실제 라벨이다. 임의로 늘리거나 줄이지 않는다.

## 규모: 3권, 14권, 40권에서 무엇이 되고 무엇이 안 되나

해시로 직접 볼 수 있다. `#home/n0` `#home/n3` `#home/n14` `#home/n40`

| 규모 | 성립 | 무너지는 곳 |
|---|---|---|
| **1권** | 성립하지 않는다 | 담당 표기 열이 전부 같은 이름이라 잉크만 쓴다. 열을 통째로 접고 기준본과 같아진다 |
| **3권** | 성립하지만 약하다 | 담당 표기가 세 이름만 반복된다. 이 규모에서는 색인보다 권 목록이 빠르므로 권 목록 절을 위로 올려야 한다 |
| **14권** | **가장 잘 맞는다** | 표제어 29개가 14권을 가로질러도 목록이 한 화면에 들어온다 |
| **40권** | 성립한다 | 색인은 그대로다. 대신 권 목록 40행이 스크롤을 잡아먹으므로 문서 묶음별로 접어야 하고, 발췌의 담당 권이 수십 곳이 되어 셋만 세우고 나머지는 수로 접는다. 표제어 검색이 유일한 실전 진입로가 된다 |

**이 안이 진짜로 잘하는 것**: 봇 이름을 모르는 사람이 시작할 수 있다.
**이 안이 진짜로 못하는 것**: 봇이 하나뿐일 때 존재 이유가 없다.

## Do's and Don'ts

**Do**
- 가장 큰 활자에 사실을 넣는다. 무엇이 현행이고 몇 권이 나누어 싣는지.
- 문서를 주어로 쓴다. "『축복 행정 규정집』 38쪽에 따르면".
- 후속질문과 표제어는 입력창에 채우기만 한다. 자동으로 보내지 않는다. 최대 3개.
- 상태는 근거 있음 / 근거 불충분 / 문서에 없음 셋으로만 말한다.
- 골드는 선으로만 쓴다.
- 능력은 기대를 배신하는 쪽만 적는다.
- 모션은 `--motion` 단일 변수로 통제한다. `animation: none !important` 를 쓰면
  OS 에서 동작 줄이기를 켠 사용자에게 수동 토글이 영구히 먹지 않는다.

**Don't**
- 그라디언트를 쓰지 않는다. 배경, 버튼, 스켈레톤 시머 전부. 스켈레톤은 단색 펄스다.
- `cite_count` 를 숫자로 노출하지 않는다. 문서 랭킹 점수일 뿐이다.
- 숫자 신뢰도(`신뢰도 62%`)를 만들지 않는다.
- 봇을 색, 별점, 대화 수, 인기순으로 구별하지 않는다. 이름과 담당 문서와 능력 표기로만 한다.
- 1인칭을 쓰지 않는다. 문서가 주어다.
- 시스템 프롬프트, 내부 분류, RAG 동작 방식을 노출하지 않는다(운영 원칙 §6).
- 근거가 없을 때 문서명이나 쪽수를 만들어 내지 않는다. 담당 권도 근거 없이 지목하지 않는다.
- 노치 폰 목업을 쓰지 않는다. 반응형 실물로 렌더하고 뷰포트만 바꾼다.
- em-dash(`—`, `–`)를 쓰지 않는다. 일반 하이픈만 쓴다.
- `window.addEventListener('scroll')` 을 쓰지 않는다.
- 라이트 모드에서 `#855BC6` 이상 밝기의 보라를 fill 로 쓰지 않는다.
- 이모지, placeholder-as-label, 균일 16px radius, 컬러 좌측 보더 스트립을 쓰지 않는다.
