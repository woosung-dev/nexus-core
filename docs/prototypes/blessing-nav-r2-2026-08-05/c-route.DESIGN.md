# 경로 (Route)

## Overview

제품 이름이 네비게이션이다. 그러면 첫 화면은 노선도여야 한다.

기준본 c 의 노선도는 「정보선 실선 / 고민선 점선」 두 개에 질문을 5개씩 매단 것이었다.
그건 지도가 아니라 **목록 두 개에 선을 그은 것**이다. 환승도 종점도 없어서 선이 아무 관계도
표현하지 않았다. 이번에는 지도의 어휘를 실제 데이터에 대응시켰다.

| 지도 | 제품 |
|---|---|
| 노선 | 승인 문서 한 종 |
| 역 | 그 문서로 답할 수 있는 질문 |
| 환승역 (금색 링) | 두 문서가 함께 답하는 질문 |
| 회색 파선 | 노선이 없는 방향 |
| 도보 구간 | 규정으로 답을 내지 않는 곳 |

이제 지도가 실제 정보를 담는다. 어떤 문서가 어떤 질문을 커버하는지, 어디가 겹치는지,
어디가 비어 있는지가 한 화면에서 읽힌다. `『축복 행정 규정집』` 과 `『축복후보자 등록 안내』`
가 만나는 지점이 `축복후보자 서류` 라는 사실은 지도에서만 볼 수 있고, 그 답변에는 두 문서가
모두 인용된다.

**감수한 위험**: 못 하는 것을 첫 화면에 그린다. 「이쪽으로는 노선이 없습니다 - 환불 · 현장 운영 ·
플랫폼 절차 · 개인 자격 판정」. 보통 제품은 못 하는 것을 첫 화면에 쓰지 않는다.
운영 원칙 §D 가 "공식 자료로 확인할 수 없으면 그렇게 분명히 말한다"이므로, 경계를 첫 화면에
두는 것이 이 제품의 정직함이다.

## Colors

**5색이다.** porcelain, ink, meta, route, gold. 여기에 파선용 hair 가 붙는다.

**노선 6개를 색으로 구분하지 않는다.** 6색을 쓰면 브랜드가 무너진다. 노선은 전부 같은
`route` 보라이고 구분은 왼쪽 이름표가 한다. 실제 노선도도 색이 없으면 이름으로 읽는다.

**색을 아낀 만큼 금색이 튄다.** 이 페이지에서 골드가 나오는 곳은 셋뿐이다.
지도의 환승 링, 답변 경로의 환승 점, 각주 번호의 밑선. 셋 다 같은 뜻이다.
"두 문서가 함께 뒷받침한다."

바탕 `#F7F6F9` 기준: ink 12.0:1, ink-2 7.1:1, meta 5.2:1, route 8.5:1, 흰 글씨 on route 9.2:1.
골드 `#C9A227` 은 2.2:1 이라 글자에 쓰지 않는다. 링과 밑선 전용이고,
글자급이 필요하면 `#6B5000` (7.0:1).

## Typography

Freesentation 900 이 표시, Pretendard Variable 이 본문, JetBrains Mono 가 판본과 쪽수다.

매스트헤드는 문장 하나다. `승인 문서 6종이 6개 노선으로 운행 중입니다`.
"어디로 가시나요" 같은 정보량 0 의 문구를 화면의 가장 큰 활자에 쓰지 않는다.

역 이름은 11.5px 로 작다. 지도의 라벨이지 제목이 아니다.
환승역만 600 굵기로 올라간다.

절차 번호는 `counter(s, decimal-leading-zero)` 로 `01 02 03` 이 된다.
**이 자리에만 번호를 쓴다.** 실제 순서가 있어서 순서가 정보를 담기 때문이다.
노선도의 역에는 번호를 붙이지 않는다. 역은 순서가 아니라 위치다.

## Layout

**노선도** 는 14칸 CSS Grid 다. 각 역이 자기 컬럼에 서고, 같은 컬럼에 두 노선의 역이
서면 그것이 환승이다. 환승 연결선은 두 점 사이를 세로 파선으로 잇는다
(런타임에 `getBoundingClientRect` 로 위치를 잰다).

노선 길이는 마지막 역까지다. 종점 뒤로 선이 이어지지 않는다.
`--drawn: calc(N% + 6px)` 로 점 반경만큼만 더 나간다.

**900px 미만** 에서는 노선을 세로로 돌린다. 각 노선이 블록이 되고 역이 아래로 흐른다.
지하철 앱의 노선별 보기와 같은 전환이다. 이때 환승 연결선은 그리지 않는다
(세로 배치에서는 컬럼 정렬이 의미를 잃는다). 대신 환승역의 금색 링이 남아 표시를 유지한다.

**대화** 는 본문 안쪽 왼쪽에 196px 경로 거터가 있다. 바깥에 사이드바도 패널도 없다.
A안(오른쪽이 무거운 2열), B안(왼쪽 사이드바 + 전폭 행)과 회색조 실루엣이 다르다.

**프로토타입 크롬** 은 상단 한 줄이다. 높이만 30px 쓰고 폭은 뺏지 않는다.
키보드로도 조작한다. `T` 테마, `M` 모션, `1`-`8` 화면.

## Elevation

**평면이다.** 앱 프레임 그림자 하나를 빼면 그림자가 없다.
지도는 종이이고 종이는 뜨지 않는다. 깊이는 선의 굵기와 여백으로만 만든다.

## Shapes

- **0px** 노선, 규칙선, 지도의 모든 구조
- **6px** 버튼, 입력, 데모 상자
- **999px** 칩, 알약, 스위치, 그리고 역과 환승 링(`border-radius: 50%`)

역이 원인 것은 장식이 아니다. 지도의 관습이다.
토큰에는 `pill: 999px` 하나로 싣는다. `50%` 는 단위가 px/rem/em 이 아니라
design.md 스키마가 받지 않으므로, 원형은 CSS 에서 직접 `50%` 로 쓰고 토큰으로 올리지 않는다.

## Components

### 노선 (line)
`[이름표 132px] [트랙 14칸]`. 이름표에는 문서 이름과 판본이 들어간다.
환승역에 커서를 올리면 그 질문이 걸린 노선들이 함께 금색으로 밝아진다.

### 역 (stop)
`[점 11px] [이름 11.5px]`. 누르면 그 질문이 입력창에 채워진다. 자동으로 보내지 않는다.
환승역은 점이 15px 이고 테두리가 3px 금색이다.

### 노선 없음 (noline)
파선 위에 놓인다. 네 항목은 실제로 이 봇이 다루지 않는 범위다.
`봇 상세 > 지나지 않는 구간` 과 같은 값을 쓴다.

### 도보 구간 (walk)
규정으로 답을 내지 않는 여섯 가지. 점선 대시가 앞에 붙어 "선로가 아니다"를 말한다.
운영 원칙 §2 의 "고민 중심 답변은 규정을 실제로 설명할 때만 근거를 붙인다"가
지도 층위에서 먼저 지켜진다.

### 답변 경로 (route)
지도의 어휘가 답변에서 다시 나온다. `질문 → 지난 문서 → 답변` 세 역이고,
가운데 역이 인용 백필의 30초를 담는다. 확인 중에는 점이 맥동하고,
확정되면 `8종 확인 · 2종 인용` 과 환승 표기가 나온다.

역 이름은 사용자 언어로만 쓴다. `FAQ 즉답` `문서 검색` `일반 LLM` 같은 내부 분기는
역이 되지 않는다. 경로는 **무엇을 근거로 삼았는가**만 말하고
**어떻게 처리했는가**는 말하지 않는다 (운영 원칙 §6).

### 답변 4유형

| 유형 | 렌더 | 경로 |
|---|---|---|
| 행정 확답 | 결론 → `근거` → `절차`(01 02 03) → `다음` | 그린다 |
| 맥락 확인 | 공감 → 확인 질문 **정확히 한 개** → 부담 낮은 칩 | 그리지 않는다 |
| 근거 없음 | 고정 거절 문장 → 부모님께 여쭐 질문 3개 → 짧은 정서 지지 | 그린다 (인용 0건) |
| 안전 우선 | 규정 안내 중단 → 안전 확인 → 어른 4단계 → 상담전화 109 | 그리지 않는다 |

어른 연결 순서 고정: 부모님 → 가정부장님 → 공직자·목회자·사모님 → 신뢰하는 가까운 어른.

## Motion

한 번의 연출만 쓴다. **노선이 그려진다.** 진입 시 6개 노선이 70ms 간격으로
왼쪽에서 오른쪽으로 자란다. 700ms, `cubic-bezier(0.2,0,0,1)`. 한 번 그려지고 끝난다.

답변 경로의 선도 같은 어휘로 자란다. 근거가 확정되면 50%에서 100%로 이어진다.
이 둘 말고 흐르는 애니메이션이 없다. 맥동하는 것은 확인 중인 역 하나뿐이고,
그건 장식이 아니라 상태다.

모션은 `--motion` 단일 변수로 통제한다. `animation: none !important` 를 쓰면
OS 에서 동작 줄이기를 켠 사용자에게 수동 토글이 영구히 먹지 않는다.

## Do's and Don'ts

**Do**
- 지도의 모든 기호가 실제 데이터를 뜻하게 한다. 선은 문서, 역은 질문, 환승은 교차.
- 못 하는 것을 지도에 그린다. 경계를 아는 것이 이 제품의 값이다.
- 노선 길이는 마지막 역까지만 그린다.
- 금색은 환승 하나에만 쓴다.
- 후속질문은 입력창에 채우기만 한다. 최대 3개.

**Don't**
- 노선을 색으로 구분하지 않는다. 6색을 쓰는 순간 브랜드가 사라진다.
- 그라디언트를 쓰지 않는다. 파선은 `border-style: dashed` 이고 스켈레톤은 단색 펄스다.
- 역에 번호를 붙이지 않는다. 번호는 실제 순서가 있는 절차에만 쓴다.
- 내부 분기를 역으로 만들지 않는다 (운영 원칙 §6).
- `cite_count` 를 숫자로 노출하지 않는다.
- 숫자 신뢰도를 만들지 않는다. 상태는 근거 있음 / 근거 불충분 / 문서에 없음 셋뿐이다.
- 1인칭을 쓰지 않는다. 문서가 주어다.
- 노치 폰 목업을 쓰지 않는다.
- em-dash(`—`, `–`)를 쓰지 않는다.
- `window.addEventListener('scroll')` 을 쓰지 않는다.
- 라이트 모드에서 `#855BC6` 이상 밝기의 보라를 fill 로 쓰지 않는다.
