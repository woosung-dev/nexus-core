# 관리자 셸 시안 2안 — 판단 기준

`compare.html` 을 브라우저로 열어 두 안을 나란히 본다. 화면 전환 버튼 2개(못 답한 질문 / 봇 상세)가 있다.

## 무엇을 고르는 것인가

**시각 언어 하나**를 고른다. 정보 구조(사이드바 4그룹, 봇 상세 5탭)는 두 안이 **동일**하다.
IA 는 이미 확정된 사항이라 비교 대상이 아니다. 두 안의 차이는 **밀도·표면·강조**뿐이다.

## 두 안

| | 안 A · 콘솔 | 안 B · 정돈 |
|---|---|---|
| 성격 | 표와 상태가 주인공. 카드를 걷어내고 실선으로 구획 | 지금의 shadcn 카드 언어를 유지하되 규칙을 통일 |
| 표 행 높이 | 34px | 48px |
| 본문 크기 | 13px | 14px |
| 한 화면에 보이는 행 | 약 18행 | 약 12행 |
| 표면 | 테두리 없는 영역 + 1px 구분선 | 카드(테두리 + 라운드) |
| 숫자 | 전부 고정폭(tabular) | 고정폭 |
| 모서리 | 6px 단일 | 8px 단일 |
| 강조색 | 앰버 1점 (활성 메뉴·활성 탭에만) | 앰버 1점 (동일) |
| 잘 맞는 상황 | 매일 여는 운영 업무, 많은 행을 훑기 | 외부 시연, 가끔 들어와 읽기 |

## 두 안의 공통 결정 (이미 반영됨)

- 사이드바를 평면 10개 → **대시보드 + 3그룹 8항목**으로. 이름 전부 한국어
- `FAQs` `Documents` 는 최상위에서 사라지고 **봇 상세 탭**으로 들어감
- `/settings` 데드링크 제거, 계정 드롭다운(로그인이 없으므로) 제거
- 라이트 전용. 다크모드 없음
- 강조색은 **한 가지만**, 활성 상태 표시에만 사용
- 모서리 반경은 **한 값만** 사용
- 빈 상태·에러 상태를 화면에 같이 그려 둠 (실제로 자주 보게 되는 상태라서)

## 볼 때 확인할 것

1. **못 답한 질문** 화면에서 한 번에 몇 행이 읽히는가. 매일 이 화면을 쓴다면 그 차이가 누적된다
2. **봇 상세** 화면에서 탭 5개가 부담스럽지 않은가
3. 표 안의 「처리 경로」 배지가 훑을 때 구분되는가
4. 외부에 보여줬을 때 어느 쪽이 덜 민망한가

## 고른 뒤

선택한 안의 수치(행 높이·글자 크기·모서리·간격)가 그대로 `globals.css` 의 토큰이 된다.
안 B 를 고르면 토큰 정리 분량이 절반으로 준다.

## 근거

- `ui-ux-pro-max` 의 제품유형 조회에서 이 화면군의 1순위 패턴이 **Data-Dense Dashboard** 로 나왔다 (안 A 의 근거)
- `taste-skill` 은 §13 에서 관리자 패널·데이터 테이블을 **명시적 범위 밖**으로 선언한다. 그래서 미감 규칙은 쓰지 않고 안티슬롭 가드레일만 적용했다
- 표본 데이터는 실제 도메인에서 가져왔으나 **수치는 예시**다
