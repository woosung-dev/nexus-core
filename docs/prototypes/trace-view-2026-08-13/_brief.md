# 턴 실행 추적 화면 — A/B 2안 (2026-08-13)

관리자가 「이 답변을 믿어도 되나」를 한 화면에서 판단하게 하는 것이 목적이다.
두 안 모두 **실측 trace 1건**(로컬 봇 29 · 메시지 #180)으로 그렸다. 지어낸 수치는 없다.

## 두 안이 공통으로 답하는 것

1. 이 턴이 8단계를 **어떻게** 지났나 (결정 + 무엇을 보고 정했나 + 소요)
2. **우리가 준 근거 vs 답변이 쓴 근거** 의 불일치
3. 어느 설정에서 나온 답인가 (프롬프트 지문 `97e05c3e` · 검색 모드 · 정책)

실측 사례에서 바로 잡힌 것: 답변이 `reg-50` · `reg-51` 을 근거로 들었는데 **둘 다 주입한 적이 없다.**
strict 게이트는 「하나라도 맞으면 통과」라 막지 않았다. 두 안 모두 이걸 최상단에 놓는다.

## A안 — 진단 콘솔

**출처**: `ui-ux-pro-max` 스킬 · `Data-Dense Dashboard` 패턴 · Real-Time/Operations

- **카드 + 그리드.** KPI 5칸, 파이프라인 가로 레일, 근거 대조 2단 패널.
- **상태색을 쓴다.** 초록(정상)·호박(주의)·빨강(결함)·파랑(비용 집중).
- **기존 관리자에 그대로 얹힌다.** shadcn 토큰 · `--radius: 0.375rem` · Geist + Noto Sans KR 그대로.
  #67 개편으로 잡아 둔 시각 시스템과 충돌이 없다.
- 가로 레일이라 **단계 간 시간 비중이 즉시 보인다**(검색 99.8%).

**강점**: 익숙하다. 스캔이 빠르다. 다른 관리자 화면과 이질감 0. 구현이 가장 짧다.
**약점**: 카드가 8개 넘게 쌓이면 「대시보드 잡음」이 된다. 색에 의미를 많이 실어서
색약 사용자를 위해 라벨을 반드시 병기해야 한다(현재 시안은 병기함).

## B안 — 판독지

**출처**: `taste-skill` · 단 **이 스킬은 §13 에서 「관리자 패널·데이터 테이블은 범위 밖」이라고 스스로 선언한다.**
그래서 랜딩용 규칙은 버리고 **밀도 9 규율과 안티슬롭 규칙만** 가져왔다. 정직하게 적어 둔다.

적용한 규칙:
- `VISUAL_DENSITY 9` → **카드 상자 금지.** 1px 헤어라인과 여백만으로 가른다.
- 모든 숫자 `font-mono` + `tabular-nums` → 자릿수가 흔들리지 않는다.
- **강조색 하나만** (`--accent` 파랑), 경보는 `--alarm` 하나. 장식용 점 0개.
- 시간 비중을 **배경 트랙 있는 막대로 그리지 않는다**(안티패턴). 밑줄 한 획으로만.
- 본문 폭 62~64ch 고정, 질문은 34ch 에서 접는다.
- 판독 문장을 **완성된 한국어 문장**으로 쓴다: 「표기 4건 중 2건이 맞아 통과시켰습니다.
  나머지 2건은 확인하지 않습니다」

**강점**: 한 턴을 **읽게** 만든다. 화면이 조용해서 이상값이 튄다. 인쇄·캡처해서 공유하기 좋다.
**약점**: 기존 관리자와 결이 다르다. 이 화면만 따로 노는 느낌이 날 수 있다.
목록에서 여러 건을 훑는 용도로는 A안보다 느리다.

## 고를 때 볼 것

| 물어볼 것 | A안 | B안 |
|---|---|---|
| 하루에 몇 건을 볼 건가 | 수십 건 훑기에 유리 | 몇 건을 깊게 보기에 유리 |
| 누가 보는가 | 운영자·관리자 | 개발자·QA·나 자신 |

**섞을 수도 있다.** 목록·요약은 A안 카드로, 상세 1건은 B안 판독지로.
그게 실제로 가장 그럴듯하지만, 먼저 둘을 각각 보고 결정하는 게 낫다.

## 두 안 모두 아직 안 담은 것

- **목록 화면**(여러 턴을 훑고 이상값만 골라내는 화면). 상세만 그렸다.
- **실패한 턴**. 예외로 죽으면 메시지 행이 없어 trace 자체가 없다(구현 한계, 문서화됨).
- **비교 보기**(같은 질문의 legacy vs strict 를 나란히). STEP 1 측정에는 이게 필요하다.
