# 블레싱 네비게이션 클라이언트 UI 시안 3종

작성일: 2026-08-05
상태: 검토용 프로토타입. 실제 코드에는 반영하지 않았다.

`index.html` 을 브라우저로 열면 세 안을 비교할 수 있다. 빌드 도구는 필요 없다.

## 결론

| 안 | 이름 | 한 줄 | 고를 이유 |
|---|---|---|---|
| A | 색인 (The Register) | 카드를 버리고 헤어라인 색인으로. 근거 패널 상시 노출 | 부모 세대 실무자가 주 사용자일 때 |
| B | 시스템 (Shipping System) | 토큰·상태·접근성을 전부 실은 출고 가능한 형태 | 이번 분기에 실제로 붙일 때 |
| C | 경로 (Route) | 답이 어떤 문서를 지나 왔는지 노선으로 표시 | 다른 챗봇과 확실히 구별돼야 할 때 |

정하기 어려우면 **B의 토큰 위에 C의 경로 레일만 얹는 조합**이 실현 가능하다.
A의 상시 근거 패널은 데스크톱 옵션으로 따로 붙일 수 있다.

## 왜 다시 그렸나

관리자 시안(로그인 + 대화, 모바일/PC)에서 걷어낸 것:

- 라일락에서 피치로 넘어가는 구름 그라데이션 배경과 반짝이
- 동일 크기 카드 4개를 세로로 쌓은 추천 질문
- 3D 렌더 일러스트와 이모지
- 로봇 아이콘 아바타
- 라벨 없는 입력창(플레이스홀더가 라벨 역할)
- PC 시안 오타 3건: 속박식 → **축복식**, 40일 정성훈 → **40일 정성**, 블레싱과 헌장활동 → **봉헌식과 탕감봉**

현행 `frontend-client` 코드에서 걷어낸 것:

- 말풍선 자체의 그라데이션(`bg-linear-to-br from-amber-400 to-amber-500`)과 컬러 글로우 그림자
- 호버 시 `scale-110` 으로 튀는 아바타
- 카드 호버 앰버 글로우 오버레이
- **한글 웹폰트 미로드** (Geist 만 실려 한글이 시스템 폴백으로 떨어진다. 지금 화면이 저렴해 보이는 가장 큰 원인)

세 안의 공통 원칙: **그라데이션 말풍선, 컬러 글로우, 튀는 아바타를 전부 버리고 위계는 타이포그래피와 여백으로만 만든다. 채도는 브랜드 퍼플 한 곳에만 쓴다.**

## 세 안이 공통으로 푸는 제품 문제

시안에는 없지만 이 제품에 이미 구현돼 있거나, 지금 화면이 놓치고 있는 것들이다.

1. **근거가 답변보다 늦게 온다.** `ChatProvider.tsx` 의 인용 백필은 2초 간격 최대 15회(30초)로 폴링한다. 그런데 기다리는 동안의 표시가 코드에 아예 없다. 사용자는 근거 없는 답으로 오해한다. 세 안 모두 이 30초를 상태로 설계했다.
2. **인용 0건과 검색 실패는 다른 상태다.** 문서를 찾아봤지만 답을 뒷받침하지 못한 경우와, 애초에 근거가 없는 경우를 화면에서 구분한다. (`인용된 자료 없음 · 검색 4건`)
3. **답변 유형이 4가지고 화면 처리가 각각 다르다.** 운영 원칙 §7 최소 평가 세트와 1:1 대응한다. 상단 툴바의 `답변 유형` 으로 바로 비교할 수 있다.
   - 행정 확답: 결론 → 근거 → 절차 → 다음 행동 4단 구조 + 인용 + 형광펜
   - 맥락 확인: 되묻는 질문 한 번에 하나, 근거 표시 없음
   - 근거 없음: 정해진 거절 문장 + 부모님께 여쭐 질문 정리 카드
   - 안전 우선: 규정 안내 중단, 연결 경로 카드, 자살예방 상담전화 109
4. **첫 화면의 두 진입점**(축복 정보 알아보기 / 고민 나누기)은 운영 원칙에 이미 정해져 있다. 두 진입점은 서로 다른 봇이 아니라 같은 봇이 답변 순서를 바꾸는 것이다.
5. **봇이 1개뿐이면 메인을 건너뛰고 바로 대화로 들어간다.** 세 안 모두 상태 갤러리에 규칙으로 명시했다.

## 지킨 코드 제약

`frontend-client/src/types/api.ts` 와 `MessageCitations.tsx` 주석에 박힌 제약을 그대로 따랐다.

- `cite_count` 는 **숫자로 노출하지 않는다**(문서 랭킹용). 배지 문구로만 표현한다.
- `approximate: true` 인 인용에는 "표시된 답변이 직접 인용한 대목이 아니라 같은 질문으로 다시 검색한 결과"라는 고지를 붙인다.
- `evidence[]` 는 항상 `content` 의 부분문자열이라 형광펜 앵커가 안전하다.
- 피드백 사유 코드는 실제 값 그대로 썼다. 긍정 `정확함/도움 됨/친절함/명확함/기타`, 부정 `부정확함/도움 안 됨/근거 부족/너무 김/부적절/기타`.
- 로그인은 하나로 SSO 아이디+비밀번호 단독. 오류는 401 / 429(약 5분) / 403(비활성) 세 가지를 그대로 썼다.
- 운영 원칙 §6에 따라 **시스템 프롬프트, 내부 분류, RAG 동작 방식은 화면에 드러내지 않는다.** C안의 경로 레일도 `FAQ 즉답 / 문서검색 / 일반` 같은 내부 분기는 역으로 만들지 않고, "어떤 문서를 지났는가"만 말한다.

## 벤치마킹에서 가져온 것

character.ai / Poe / ZETA / 뤼튼 크랙 / Talkie / JanitorAI / Chub / GPT Store / NotebookLM / Perplexity / Onyx / Glean 을 조사했다. 이 카테고리는 둘로 갈려 있다. 소비자용 캐릭터 포털은 **그림과 인기**로 경쟁하고, 기관용 어시스턴트 디렉터리는 **출처**로 경쟁하며 별점과 사용량 표시를 오히려 걷어냈다.

가져온 것:

- **레일 이름을 분류 라벨이 아니라 편집자의 말투로.** "인기 / 신규"가 아니라 "축복식을 처음 준비하신다면", "담당 문서로 고르기". 레일마다 왜 존재하는지 한 줄을 붙였다. 격자가 템플릿으로 읽히는 것을 막는 가장 싼 방법이다.
- **카드 위의 숫자를 전부 출처로 교체.** 대화 수가 놓이던 자리에 `문서 6종 · 2026 정본` 을 넣었다. 이 목록에서 가장 효과가 큰 교체다.
- **NEW/HOT 배지 대신 추천 사유 한 문장.** "2026 개정 규정집을 단독으로 보유", "최근 공문 2건이 반영됨". 배지는 주장만 하고 문장은 근거를 준다.
- **수정일과 판본을 봇 상세에 필수로.** 소비자 서비스에는 전부 없고 기관용 도구에는 전부 있는 항목이다. 규정 코퍼스에서는 가장 무거운 정보다.
- **담당 범위 / 다루지 않는 범위 / 확신도 표기 / 에스컬레이션 경로**를 스캔 가능한 속성 행으로. Microsoft 의 Data & tools 탭과 Glean 의 연결 소스 목록에서 가져왔다.
- **인용된 자료와 검색된 자료를 분리.** Onyx 의 `Cited Sources` / `Found Sources` 패턴이다. 우리 프로젝트의 "인용 0건 ≠ RAG 미작동" 문제를 화면에서 읽을 수 있게 만든다.
- **대화 시작 질문을 CTA 로.** GPT Store 는 별도 시작 버튼 없이 4개의 시작 질문이 CTA 역할을 한다.
- **정해진 거절 문장.** NotebookLM 은 코퍼스 밖 질문에 고정된 한 문장으로 답한다. 매번 다르게 얼버무리면 사용자는 경계를 배우지 못한다.

일부러 **가져오지 않은** 것:

- **인물 초상 아바타와 하단 그라데이션 스크림.** 이 카테고리에서 가장 많이 복제된 장치지만 롤플레이·컴패니언 신호와 분리되지 않는다. 축복 안내 봇에 붙이면 데이팅 앱과 한 발짝 거리다. 대표봇만 실제 엠블럼을 쓰고 나머지는 모노그램으로 갔다.
- **별점, 좋아요, 팔로워, 대화 수.** GPT Store 는 격자에서 별점을 걷어냈고, 그 결과 제작자들이 설명 문자열에 `4.0 ★` 을 직접 써넣고 있다. 기관용 제품에서 인기 수치는 "가장 많이 쓴 답이 맞는 답인가"라는 잘못된 질문을 만든다.
- **네온·그라데이션 카드 테두리, 이모지 분류 체계, 무한 스크롤.** 마지막 것은 이 카테고리에서 실제로 쓰는 곳이 거의 없다.
- **데스크톱에서 480px 한 칼럼.** ZETA 는 1044px 뷰포트에서 본문이 480px 다. 우리는 웹이 출시 형태다.

## 기술 메모

- **자립형 정적 HTML.** 빌드 도구 없음. 외부 의존은 폰트 CDN 뿐이다. `file://` 로 직접 열어도 동작하도록 `<script type="module">` 과 로컬 `fetch` 를 쓰지 않았다(둘 다 Chrome 이 `file://` 에서 막는다).
- **반응형은 미디어 쿼리가 아니라 컨테이너 쿼리.** `<html data-viewport>` 로 프레임 폭을 바꾸고 내부는 `@container app (min-width: …)` 으로 반응한다. 미디어 쿼리로 하면 27인치에서 "모바일" 토글이, 노트북에서 "데스크톱" 토글이 깨진다.
- **모션은 단일 변수로 통제.** `--motion` 을 0/1 로 두고 모든 transition 이 `calc(var(--motion) * Nms)` 를 쓴다.
  `@media (prefers-reduced-motion: reduce) { * { animation: none !important } }` 는 **쓰지 않았다.** 그렇게 하면 macOS 에서 손쉬운 사용의 동작 줄이기를 켠 사용자에게 수동 토글이 영구히 먹지 않는다.
- **스트리밍 타이핑은 `Intl.Segmenter('ko', {granularity:'grapheme'})`** 로 분절한다. 화면 전환 시 `AbortController` 로 중단해 숨은 화면에서 계속 돌지 않게 했다.
- **폰트** (전부 실제 응답 확인함)
  | 용도 | 선택 | 비고 |
  |---|---|---|
  | 본문·UI (공통) | Pretendard Variable 동적 서브셋 | weight 축이 **45–920**. 100/900 이 아니다 |
  | A안 디스플레이 | Paperlogy 6/7/9 | jsDelivr 에 CSS 가 없어 `@font-face` 직접 작성 |
  | C안 디스플레이 | Freesentation 7/9 | 동일 |
  | 라틴·숫자 | Instrument Sans | Pretendard 와 x-height 가 맞는다. Geist 는 혼용 시 어긋난다 |
  | 모노 | Geist Mono (A·B) / JetBrains Mono (C) | |

  채택하지 않은 것: Wanted Sans Variable 은 축이 400에서 시작해 300 캡션이 불가능하다. SUIT Variable 은 서브셋 없는 624KB 단일 파일이다.
- **엠블럼**은 관리자 시안 PNG(941×1672)에서 `box=(124, 237, 356, 469)` 로 잘라낸 뒤 휘도를 알파로 바꾼 마스크다(10.6KB). `mask-image` 로 쓰기 때문에 테마에 따라 색만 바뀐다. 각 HTML 에 base64 로 인라인돼 있어 파일 하나만 보내도 열린다. 원본은 `assets/emblem.png`.

## 검증 상태

- 8화면 × 3파일을 1440px 과 390px, 라이트와 다크 양쪽에서 확인
- 콘솔 에러 0 (`favicon.ico` 404 는 정적 서버 쪽 응답이라 페이지 오류가 아니다)

## 다음 단계 (안을 고른 뒤)

1. `frontend-client/src/app/globals.css` 의 `--primary` 를 앰버에서 브랜드 퍼플로 교체하고, 선택한 안의 토큰 블록을 Tailwind v4 `@theme` 로 옮긴다. B안의 토큰 블록이 그대로 들어간다.
2. `app/layout.tsx` 에 Pretendard 를 추가한다. 현재 Geist 만 로드돼 한글이 시스템 폴백으로 떨어진다.
3. `.dark` 가 라이트 값을 복사하고 있는 것을 걷어내고 실제 다크 토큰을 넣는다. 필요 없다면 `<html className="dark">` 을 지운다.
4. `ChatProvider.tsx` 의 인용 폴링에 **대기 상태를 노출**한다. 지금은 상태 자체가 없어서 UI 를 붙일 수 없다.
5. 백엔드 응답에 **검색된 문서 목록**(인용되지 않은 것 포함)을 추가해야 `인용 / 검색` 분리 표시가 가능하다. 현재 `Citation[]` 에는 인용된 것만 온다.
6. 봇 상세 라우트(`/bots/{id}`)를 새로 만든다. 필요한 필드는 `BotResponse` 에 이미 있고, 수정일과 판본만 추가하면 된다.
