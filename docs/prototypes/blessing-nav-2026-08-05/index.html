클라이언트 화면 시안 3종

관리자 시안의 색상과 엠블럼만 이어받고, 정보 구조와 디자인 언어는 다시 설계했습니다. 세 안 모두 같은 8화면, 같은 예시 데이터, 같은 반응형 규칙을 씁니다. 다른 것은 디자인 언어와 메인 화면의 논리, 그리고 근거를 보여주는 방식입니다.

화면의 봇 이름, 문서명, 규정 내용, 인용문은 전부 UI 검토용 예시입니다. 실제 규정이나 승인 문서가 아닙니다. 시안의 오타는 바로잡아 실제 용어를 썼습니다. 속박식 → 축복식, 40일 정성훈 → 40일 정성, 블레싱과 헌장활동 → 봉헌식과 탕감봉.

세 안이 공통으로 푸는 문제

시안에는 없지만 이 제품에 이미 있는 것, 그리고 지금 화면이 놓치고 있는 것입니다.

  • 01근거가 답변보다 늦게 온다. 인용은 2초 간격으로 최대 15회, 30초까지 걸립니다. 지금은 기다리는 동안 화면에 아무 표시가 없어 사용자가 근거 없는 답으로 오해합니다. 세 안 모두 이 30초를 설계했습니다.
  • 02인용 0건과 검색 실패는 다른 상태입니다. 문서를 찾아봤지만 답을 뒷받침하지 못한 경우와, 애초에 근거가 없는 경우를 구분해서 보여줍니다.
  • 03답변 유형이 네 가지고 화면 처리가 각각 다릅니다. 행정 확답 · 맥락 확인 · 근거 없음 · 안전 우선. 뒤 두 가지는 어떤 시안에도 없었지만 운영 원칙이 요구하는 상태입니다. 상단 툴바에서 바로 전환해 비교할 수 있습니다.
  • 04첫 화면의 두 진입점은 운영 원칙에 이미 정해져 있습니다. 축복 정보 알아보기와 고민 나누기. 두 진입점은 서로 다른 봇이 아니라 같은 봇이 답변 순서를 바꾸는 것입니다.
  • 05카드 위의 숫자를 전부 문서에 관한 사실로 바꿨습니다. 캐릭터 AI 서비스가 대화 수를 놓는 자리에 근거 문서 수와 판본을 넣었습니다. 별점, 인기순, 팔로워는 이 제품에서 아무것도 증명하지 못합니다.
  • 06한글 웹폰트를 실제로 싣습니다. 현재 앱은 Geist 만 로드해 한글이 시스템 폴백으로 떨어집니다. 자간과 굵기가 통제되지 않는 것이 지금 화면이 저렴해 보이는 가장 큰 원인입니다.

고르는 기준

이럴 때고를 안이유
부모 세대 실무자가 주 사용자다A장식이 가장 적고 문서가 화면의 주인공이다. 근거 패널이 항상 열려 있어 규정을 확인하러 온 사람에게 가장 빠르다.
이번 분기 안에 실제로 붙여야 한다B토큰과 상태가 그대로 코드로 옮겨진다. 다크모드와 접근성 수치까지 이미 정리돼 있어 구현 위험이 가장 낮다.
다른 챗봇과 확실히 구별돼야 한다C경로 레일은 이 제품에서만 성립하는 장치다. 다른 서비스에 붙여넣을 수 없다.
2세 청년 유입을 늘리고 싶다C 또는 BC는 인상이 강하고, B는 익숙한 앱 문법이라 학습 비용이 낮다.
정하기 어렵다B + C 조합B의 토큰 위에 C의 경로 레일만 얹는 조합이 실현 가능하다. A의 상시 근거 패널은 데스크톱 옵션으로 추가할 수 있다.

보는 방법

  • 각 파일 상단의 검은 툴바는 제품 화면이 아니라 검토용 도구입니다. 실제 화면에는 나오지 않습니다.
  • 화면 드롭다운으로 8개 화면을 이동합니다. 주소창 해시로도 되니 a-register.html#thread 처럼 특정 화면을 바로 공유할 수 있습니다.
  • 답변 유형 드롭다운으로 행정 확답 · 맥락 확인 · 근거 없음 · 안전 우선 네 가지를 비교합니다. 근거가 늦게 도착하는 연출은 대화 진행 화면에 들어가면 자동으로 재생됩니다.
  • Desktop / Mobile 토글은 창 크기와 무관하게 동작합니다. 컨테이너 쿼리를 써서 27인치에서도 모바일 화면이 정확히 390px 로 보입니다.
  • 라이트 / 다크 / 자동, 모션 On / Off 도 세 안 모두 동작합니다. 자동은 OS 설정을 따릅니다.
  • 인터넷이 없으면 한글 웹폰트가 시스템 폰트로 대체됩니다. 레이아웃은 그대로지만 자간이 달라집니다.
