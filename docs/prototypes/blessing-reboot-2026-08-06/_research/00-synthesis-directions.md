# 종합: 디자인 방향 A~C 제안 (확정)

작성일 2026-08-06. `01-global-chatbots.md` · `02-korean-market.md` · `03-rag-citation-ux.md` · `04-design-trends-antislop.md` 종합.

## 조사가 수렴하는 결론 5가지

1. **AI 응답은 말풍선이 아니라 전폭 문서로.** Perplexity가 가장 급진적으로 실증("버블은 메신저를 신호하고 툴 프레이밍을 해친다"). 사용자 발화만 말풍선. 진지한 정보 제품의 예외 없는 공통 패턴.
2. **랜딩=제품이 지배적.** ChatGPT("Ready when you are"), Pi(첫 발화가 온보딩), Perplexity(중앙 입력창), Meta AI 모두 스크롤 마케팅 페이지 없이 접속 즉시 대화. 네이버조차 별도 챗봇 앱을 접고 검색창 안에 이식(AI탭, 2개월 400만). 이미 신뢰가 형성된 공동체 사용자에게는 더더욱 유효.
3. **주조색 1개 + 그레이스케일이 국내 세련됨의 공식.** 토스 `#3182f6`, 카카오 `#FEE500` — 위택스봇(8색 난립, font-family 0건, radius 무스케일)이 정확한 반례. 한글 웹폰트 명시 로드 + `word-break: keep-all` + 4px 배수 radius 스케일 + SVG 아이콘이 기본기.
4. **캐릭터성은 걷어내는 게 업계 궤적.** SKT 에이닷(캐릭터 축소), 채널톡(눈→입, "귀여운 친구"→"차분한 어시스턴트"), Character.AI(눈부심 반발). 신뢰형 제품은 절제된 어시스턴트로 수렴.
5. **세리프 부활은 유효하나 무비판 채택은 새 슬롭("tasteslop").** Perplexity·Claude·Runway가 채택했지만 "왜"가 있어야 함 — 우리는 "규정 문서를 다루는 서비스=인쇄물의 권위" 라는 명확한 근거가 있음. 국소 사용(표제·인용문)으로 한정하면 안전.

6. **인용 UX의 업계 표준 (03 조사, 12개 제품)**: 순수 `[1]` 각주만 쓰는 곳 없음(칩·hover 팝업·배지로 강화가 표준) · 신뢰도 %·색상 경고배지 노출 0건 · 스트리밍 중 미완성 마커 숨김(Onyx) · 인용 카드엔 문서명+조항·버전까지 · "인용 없음"≠"근거 없음" UI 동일시 금지. 차별화 기회: Onyx의 Cited/Found 분리, NotebookLM의 "봇이 아는 문서" 소스 패널(엔드유저 투명성 최고), 규정 원문 뷰어 병치(웹검색형 제품이 못 하는 것).

## 디자인 방향 3안

### 방향 A — 「서재의 안내자」 (Warm Editorial)
- **명제**: 규정을 다루는 서비스는 도서관 사서처럼 말한다 — 따뜻하되 정확하게.
- **비주얼**: 크림/오프화이트 캔버스(Claude `#faf9f5`, Pi `#FAF3EA` 계열) + 세리프 디스플레이(표제·인용문 국소) + 본문 산세리프. 보라는 잉크 톤으로 가라앉혀 텍스트·밑선 액센트로만. 잡지식 비대칭 편집, 인용구 독립 조판.
- **랜딩**: Pi식 "첫 화면이 곧 첫 인사" — 봇이 먼저 말을 걸고 즉시 입력 가능. 아래로 짧은 에디토리얼 섹션(무엇을 근거로 답하는가).
- **채팅**: 전폭 문서형 답변 + 세리프 인용 블록. 규정 원문 발췌가 "책에서 옮겨 적은 문장"처럼 보이는 조판.
- **참고**: Claude(크림+슬랩세리프+코랄), Pi(웜 베이지+그린), 의료 AI의 딥 플럼·잉크·크림.
- **리스크**: 세리프 남용 시 tasteslop — 국소 사용 원칙 필수.

### 방향 B — 「정갈한 창구」 (Restrained System)
- **명제**: 신뢰는 장식이 아니라 정확한 정렬과 절제에서 나온다.
- **비주얼**: 모노크롬 베이스 + 극단적 타이포 튜닝(사이즈별 네거티브 자간, 커스텀 웨이트) — Linear 문법(72px/-1.58px, 510 웨이트)의 한국어 번안. 보라는 인터랙션 상태(호버·포커스·CTA)에만 국소. 순백이 아닌 니어화이트/니어블랙.
- **랜딩**: ChatGPT식 "제품=랜딩" — 최소한의 헤드라인 + 즉시 입력창 + 밑에 절제된 안내. 카피가 기능을 말함("문서에 없는 것은 답하지 않습니다").
- **채팅**: 그레이스케일 위주 인터페이스, 답변 위계는 색이 아닌 웨이트·자간·규칙선으로.
- **참고**: Linear 2025(`#0f1011`, 절제 액센트), ChatGPT(무채색+저채도 회색 액센트), 토스(주조색 1+그레이 6단계, 마이크로 a11y 디테일).
- **리스크**: 차갑게 읽힐 수 있음 — 카피 톤으로 온기 보완 필요.

### 방향 C — 「근거가 보이는 답」 (Transparent Grounding)
- **명제**: 인용 구조 자체가 미학이다 — 신뢰가 상품인 도메인에서 투명성이 가장 강한 세련됨.
- **비주얼**: 시각 스타일은 중립(뉴트럴+보라 국소)으로 두고, 정보 구조가 주인공: 발행처 알약, 검색 영수증("근거 N건 · 규정집 2권 검색"), 문서 패널(Artifacts식 사이드 캔버스), "이 창구가 답하지 않는 것" 명시 섹션.
- **랜딩**: "무엇을 알고 있는가"를 먼저 보여줌 — 근거 문서 서가가 히어로. 챗봇이 아니라 "문서고에 질문하는 창구"라는 프레이밍.
- **채팅**: Perplexity식 리포트 레이아웃 + Glean식 접힌 과정 카드 + 규정 원문 사이드 패널.
- **참고**: Perplexity(인용 내장 리포트+Sources 탭), Glean("제목+N개 완료"), Onyx(문장 단위 추적), NotebookLM 소스 패널, Mercury(규제 정보를 숨기지 않는 카피).
- **리스크**: 정보 구조 백엔드 선행과제와 결합도 높음(프로토타입은 목데이터로 무관).

## 6안 배분 제안 (스킬 × 2)

각 방향을 서로 다른 스킬 2개가 해석 → 방향별 2해석 확보, 스킬별 2안 충족:

| | ui-ux-pro-max | frontend-design | taste-skill |
|---|---|---|---|
| ui-a / fd-a / ts-a | 방향 A | 방향 B | 방향 C |
| ui-b / fd-b / ts-b | 방향 C | 방향 A | 방향 B |

(사용자 인터뷰에서 조정 가능 — 특정 방향 제외/집중 등)

## 방향별 인용 UX 매핑 (03 조사 조합안 연결)

- 방향 A ← 균형 조합의 부드러운 판: 각주 배지 + hover/tap 원문 발췌 팝업, 인용 블록은 세리프 조판
- 방향 B ← 균형 조합(권장안) 그대로: 각주+형광펜 스니펫 카드 + "이 봇이 아는 문서" 시트
- 방향 C ← 실험 조합: 원문 뷰어 병치 + Cited/Found 2구획 + 검색 타임라인 + 문서 배지(단색, C2PA 원칙과 무관하게도 신호등 금지가 업계 표준으로 재확인됨)

## 인터뷰 확정 (2026-08-06)

1. **랜딩 = 혼합형**: 상단은 즉시 질문 가능한 대화 진입점, 아래로 짧은 소개 섹션(무엇을 근거로 답하는지, 문서 서가 등)
2. **배분 = 3방향 교차**: ui-ux-pro-max → ui-a=A(서재)·ui-b=C(근거) / frontend-design → fd-a=B(창구)·fd-b=A(서재) / taste-skill → ts-a=C(근거)·ts-b=B(창구) — 방향별 2해석 확보
3. **인용 UX = 방향별 차등**: A·B 시안은 균형안(각주+발췌 팝업+형광펜 카드), C 시안은 실험안(원문 뷰어 병치+검색 타임라인+Cited/Found 분리)
4. 앞선 인터뷰 확정: 화면 범위=랜딩+채팅 2화면(파일 내 전환), 계승=완전 백지(라이선스 자유 폰트만 사용), 뷰포트=데스크톱 우선(1440)+모바일(390) 대응
